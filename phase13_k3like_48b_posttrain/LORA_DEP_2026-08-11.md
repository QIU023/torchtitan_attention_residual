# LoRA and DEP cannot be combined: the vision stage has nothing to train

Found by running the multimodal matrix on BOTH arms with DEP on, which is the first time
that combination has been exercised.

## The result

`kimi_k3_debugmodel_report_arch_lora`, DEP=1, dynamic CP=1, 10 steps:

| | cells |
|---|---|
| pass, 10 | `dp1 fsdp2 cp2 tp2 fsdp2_tp2_cp2 ep2_fsdp2 ep2_fsdp2_tp2_cp2 ep8_fsdp8 tp4 cp4` |
| fail, 8 | `pp2 pp4 pp8 fsdp2_tp2_pp2 tp2_pp2_cp2 fsdp2_pp2_cp2 ep2_fsdp2_tp2_pp2 ep2_fsdp2_pp2_cp2` |

Every non-PP cell passes. Every PP cell fails, with

    ValueError: Optimizer param_groups pattern '.*' matched no parameters
    torchtitan/components/optimizer.py:188 in _build_param_groups

The full-parameter arm is 18/18 and byte-identical to its previous table, so this is
specific to LoRA.

## Attributed by control, not by the signature alone

The signature was already strong -- DEP only engages when `pp>1`, which is exactly the
failing set -- and the log names the culprit: rank 0's stage owns
`['vision__0', 'embed_tokens']`. But the same cell was run both ways:

    LoRA + pp2, DEP on     ValueError, no parameters matched
    LoRA + pp2, DEP off    trains: 12.04920, 12.05721, 12.07554

## Why

DEP puts the vision tower on its own pipeline stage. LoRA adapts neither part of what that
stage holds: the tower is not in `DEFAULT_LORA_TARGETS`, and the embeddings that ride with
it are frozen under LoRA by construction. The stage therefore owns zero trainable
parameters, and the optimizer's `.*` pattern legitimately matches nothing.

Note this is not a bug in the optimizer's check. That check exists to catch pattern typos,
and it is doing its job -- it simply cannot know that the empty match came from a
deliberate combination of two features.

## What changed

A guard in `parallelize_kimi_k3`, fired only when PP is on, DEP is on, and the model
actually carries LoRA wrappers:

    KIMI_VIT_DEP=1 cannot be combined with LoRA yet: DEP puts the vision tower on its
    own pipeline stage, LoRA adapts neither the tower nor the embeddings, and a stage
    with no trainable parameters has no optimizer group. Run LoRA without DEP, or make
    the tower a LoRA target.

That replaces an error naming neither feature with one naming both and giving the two ways
out. It is a limitation made explicit, NOT a fix -- the fix is either adapting the tower
(a real feature, and the report trains MoonViT-V2 jointly so adapters there are not
obviously wrong) or teaching the DEP layout to keep at least one adapted module on the
vision stage.

## Two annotations this retires

* `LORA_MATRIX_18_2026-08-07`'s "18/18" was already marked stale for its three TP+CP
  cells. **Those now pass** -- defect 2 was fixed on 2026-08-10 -- so that half of the
  annotation is retired. Its numbers were taken WITHOUT DEP, which is why they never saw
  this.
* The LoRA arm's TP+CP cells passing is independent confirmation that the defect-2 fix
  carries beyond the full-parameter flavor.
