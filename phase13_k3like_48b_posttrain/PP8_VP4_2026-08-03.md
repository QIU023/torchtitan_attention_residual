# PP8 and PP8 x VP4 after the alpha and fla changes

Re-run because this session changed the alpha operator (bf16 -> FP32) and the
fla shim binding (class-level -> per-instance), both of which sit on the PP path.

## PP8 works

`kimi_k3_mini_pp8vp4` (30 layers, all-MLA), 8 GPUs, dp_shard=1:

    pp8 (VP=1)   step 1 loss 7.70497   step 2 loss 7.16346

Two constraints had to be satisfied to get here, and they are worth writing down
because they are not obvious:

**Layer count.** The virtual-stage count must be divisible by
`pipeline_parallel_degree` and give at least 2 stages per rank for VP, and it
counts the two AttnRes tail modules alongside the decoder layers. At 21 layers
that is 23 virtual stages, which is not divisible by 8 at any
`layers_per_stage`: lps=3 gives 8 (one per rank, below VP's minimum) and lps=2
gives 12 (not divisible). 30 layers gives 30+2 = 32 at lps=1 -- exactly 4 per
rank, which is VP4.

**Attention type.** pp8 on 8 GPUs forces dp_shard=1, and without FSDP's
mixed-precision cast the KDA params stay fp32 and fla's kernel asks for
108,160 B of shared memory against this GPU's 101,376 B. The flavor is all-MLA
for that reason; the PP/VP machinery under test is attention-type agnostic.

## VP4 found two real defects in AttnRes, one fixed

**Empty block list on early virtual stages. FIXED.** With 4 virtual stages per
rank the early ones sit entirely inside the first block, having crossed no
boundary, so `stack_blocks` got an empty list and raised "stack expects a
non-empty TensorList". Delta mode already guarded this; the non-delta branch did
not. VP1 never hits it because a rank's single stage always spans a boundary.

**Empty stacks cannot cross P2P. NOT FIXED.** With the guard in place the run
reaches `ValueError: Tensors for P2P must be non-overlapping and dense`. Adding
`.contiguous()` does not help -- a zero-element tensor is not acceptable to the
P2P path at all, so this is not a layout problem.

That is a design question, not a patch: a stage that produced no new blocks must
still send *something* with a static shape, and "nothing" is not sendable. The
options are a sentinel of shape (1, ...) that the receiver drops, or hoisting
the block-count contract so every stage sends the same non-zero count. Choosing
between them needs the adapter's static-shape invariant thought through, and the
adapter is the piece with the clean per-parameter record (0.00000 over 548
parameters at pp2/pp4/pp2xvp2/pp4xvp2 -- note those were measured at 21 layers,
where this path does not arise).

So: PP8 verified. PP8 x VP4 blocked on a real, newly-surfaced gap that VP4 at
this layer count is the first configuration to reach.
