## MoonEP, PR 4751 (draft)

The day's work, in order.

1. **Refactored to where torchtitan keeps transports.** Upstream has no model-local comm backend: DeepEP and HybridEP primitives live in `distributed/deepep/`, their dispatchers in `models/common/token_dispatcher.py`, and `make_token_dispatcher_config` is the single seam. MoonEP now follows that, the model folder keeps 49 lines of wiring, two class variables became one `requires_ep`, the SM budget is a module constant, and `kimi_k3_debugmodel_moonep` plus the h100 cell `kimi_k3_moonep_fsdp4_ep4` make the backend reachable at all, which it was not.
2. **A review from another session, checked claim by claim.** Five of its six findings hold. The blocker is that the branch targeted MoonEP `2bd860b` while the public release `33327eb` of 09-20 changed the interface, and nothing pins the package. The silent one is that the backward recomputes from expert slots a later micro-batch's forward overwrote, which any 1F1B schedule does: measured at 1.05 to 1.30 relative error on two H100s, fixed by refilling the slots for the saved plan, after which interleaved equals sequential bitwise and a seeded four-GPU cell is unchanged. The sixth, empty groups in the grouped GEMM, is not an issue on this torch, and a first attempt to show otherwise was an artefact of `.sum().backward()`.
3. **Ported onto the public release.** Separate local rows and prefetch pool, fences inside the kernels, compact `cu_seqlens`: the per-owner mapping loop, the private-context reach, the two group barriers, the `[E]` fp32 gradient table and the global offsets all go, 131 lines added against 205 removed. Verified so far: the CPU files pass and the interleaving probe is bitwise on two H100s against the release. **Not yet run on the release: the on-device test and the h100 cell.** The body's requirements section still names the old pin.

Still open on this PR, in the order they matter: the DeepEP comparison, which is the comparison the report makes and the only positive result this PR lacks; it needs no RDMA, since `EP_DISABLE_GIN=1` with the NVSHMEM variables is what torchtitan's own 8-GPU CI script uses. Then a perf cell that is actually a perf cell, with compile on, determinism off and a per-rank token count near the target, because the step-time table in the body comes from the deterministic numerics cells where a step is 5.2 seconds. Then one buffer and one pool shared across layers, which the release's interface now allows, and a PP cell.
