## Overnight of 09-22, what moved after the status above was written

**veRL item 6 is closed.** LoRA composes with context parallel through the engine's own path, `model.lora.rank` with torchtitan's `LoRATransform`: three steps on four cards, `rc=0`, log-prob diff 0.160 / 0.144 / 0.144, and 0.161 / 0.147 without CP. The 09-19 re-run's inheritance error belongs to the other path, a flavor baking LoRA in at build time. Two silent failures were in the way. verl's default `target_modules` are other frameworks' spellings, so the transform matched nothing, froze every other config and handed the optimizer a model with no trainable parameter, which surfaced as a missing `grad_fn` inside the first backward; the engine now refuses that configuration and names the projections the model carries (`04e55506`). And torchtitan's LoRA specialization named its forward argument `input_XI` where the parent linear says `input`, which breaks every `local_spmd` sharding config the moment a LoRA transform wraps it; the tree keeps the parent's name now (`071a58230`), and that is a finding for upstream too.
