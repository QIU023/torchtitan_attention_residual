# The 18-cell matrix on torchtitan's SDPA backend priority (2026-08-09)

Supersedes `MATRIX_18_FP32NORM_2026-08-09.md`. The losses moved because MLA's inner
attention is now torchtitan's shared `ScaledDotProductAttention` (review finding 58)
instead of a local copy, and that module wraps the call in
`sdpa_kernel([CUDNN, FLASH, MATH], set_priority=True)`. A different kernel is selected,
so the numbers differ from step 1 -- pure forward, no update involved.

**This is alignment, not a fix.** The previous numbers came from PyTorch's default
dispatcher; these come from the priority list every other torchtitan model already uses.
Neither is more correct than the other as arithmetic; being the same as llama3, qwen3 and
deepseek_v3 is the point.

Criterion for a numerics-changing change is convergence, not bit-identity, and all ten
runnable cells converge as before -- 2.1 to 2.3 over ten steps, same spread as the previous
table. Step-1 relative differences are 1.1e-5 to 3.6e-4, the scale of a different bf16
attention kernel. The same three TP+CP cells fail, for the documented
`KIMI_VIT_DYNAMIC_CP=0` reason.
