# The 18-cell multimodal matrix on the new tree (2026-09-05)

The question: with TP/SP on the declarations, can the new tree (main `390e2985b`, spmd_types
default) run the 18 cells of `MATRIX_18_CORRECTED_2026-08-09.md`? Not from any one branch:
CP stacks on the declarations, not on TP/SP, and PP sits on a rebase nobody has combined with
either. So one scratch integration branch, `mm18_int` (fork, `40bb5bbb7`):

    tpsp_review3 c0ab32d07 (declarations + clip grouping + TP/SP + tower typing)
      + cherry-picks of cp_review5's three commits (stack copy, CP layer, gym port)
      + merge of pp_rebased_local bf1d06dff (the PP line on main 60d0f7a25)

## What the merge decided

- `model.py` `update_from_config`: TP/SP's `enable_sp` stays; CP's KDA-kernel check stays; the
  declarations are issued at `tp > 1 or spmd_types` as TP/SP wrote it.
- `model.py` vision splice: the CP path comes first (the rank's slice of the tower output,
  masked-scattered into its sequence shard); the SP path (gather the shard, splice whole,
  cut back in `forward`) second. CP together with SP is refused (`NotImplementedError`, the
  CP branch's own stance for the DTensor case): the splice under SP needs the whole sequence,
  which a CP shard does not have. So the three TP x CP cells run with
  `--parallelism.no-enable-sequence-parallel`.
- `model.py` `forward`: PP's incoming block stack (`block_residual_in`) plus the declarations'
  `multimodal_context` prep, SP re-shard and type asserts; the stack starts from the received one
  on a later stage, else from the empty cut of the stream (the layout carrier).
- `parallelize.py`: no parallelism is listed unsupported any more (TP/SP's list said PP, PP's
  said TP and CP); the CP hook and the PP split / `pipeline_kimi_k3` both stay.
- The two `features.py` lists keep both the cp2 and the pp8 x vp4 cells.
- 33 CPU tests (PP layout, stage, FQN injection; CP attention) pass on the merged tree.

## The run

`matrix_scripts/mm18_matrix.sh`: `kimi_k3_debugmodel` (33 layers on this tree), seed 42,
`--debug.deterministic`, 4096 tokens per step in 256-token micro-batches (the PP tables' batch,
seed checkpoint `.mx3_seeds_main33/..._49ffe72a4588` shared with them), 8 pipeline
micro-batches, spmd_types on every cell, Attention Gym `b19162e` on `PYTHONPATH`, per-cell warm
pass then a 10-step measure pass. The CP cells use the `kimi_k3_debugmodel_cp2` recipe flavor
with the degree overridden where needed. Three streams: 2-GPU cells on GPUs 0-1 and 4-GPU
cells on GPUs 2-5 concurrently, the nine 8-GPU cells serial afterwards.
