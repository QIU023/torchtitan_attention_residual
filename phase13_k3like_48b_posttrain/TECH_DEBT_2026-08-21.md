# 两笔欠债(2026-08-21)

两件都不挡当前交付,但会挡**4025 合并之后的正式 PR**。写下来是因为它们目前只存在于对话里,
而两者都不是"补一处代码"能收掉的。

## 一、完整 TP 声明式迁移(Step 2)

### 现状

上游 **llama3 / qwen3 / deepseek_v3 / qwen3_5 / gpt_oss 五个模型全部零命令式 TP**,
一律 `model.parallelize(parallel_dims)` 一行。我们仍有 `apply_tp_kimi_k3`,880 行量级的命令式计划。

### 为什么之前的"声明式重构"没有覆盖它

`71167807b`(08-13)的提交信息原话:

> **"Step 1 of the migration to upstream's declarative path, and it is deliberately behaviour-free"**
> **"64 modules already carried a sharding_config, but ... they were declaring into the void"**

那次只做了**激活已有声明**,并刻意保持行为不变;命令式计划完整保留,两套机制并存,由矩阵检查一致。
**它从未打算迁移 TP。** 我一度把 "Step 1" 读成"全量重构",由此对树的状态判断错了好几次。

### 为什么不能只"补边界"

树里 88 个 `_tp_shard` 声明**只声明权重、不声明激活边界**:

| 声明 | 数量 | 带输出重分布 |
|---|---|---|
| `S(0)` colwise | 61 | 无 |
| `S(1)` rowwise | 27 | 无 |
| embedding `S(0)` | 1 | **有**(2026-08-21 补) |

在命令式计划还在的前提下,这是**正确的设计** —— 边界由 `ColwiseParallel`/`RowwiseParallel` 的钩子承担。
所以"缺边界"不是遗漏。

实测过一次直接补边界:`partial_dtensor` 的 tp2 从 `7.72269 / 3.2363` 变成 `7.72394 / 3.2255` ——
**边界叠加了**。已回退。同一份声明无法同时服务两个后端。

### 真正的范围:换一套张量约定

| | partial_dtensor(现状) | spmd_types(上游) |
|---|---|---|
| 激活常态 | **DTensor**,计划里清一色 `use_local_output=False` | **本地张量 + 标注** |
| 落地点 | 只在 SDPA / fla 内核处 `to_local` | 由声明的 placement 驱动 |

命令式计划里唯一 `use_local_output=True` 的是 `inner_attention`,注释写着 SDPA 没有 DTensor 规则、
必须看到本地张量。也就是说 **partial_dtensor 的设计是"全程 DTensor,只在内核处落地",
而 spmd_types 是相反的约定**。

所以迁移要改的不只是 `parallelize.py`,还有 MLA / KDA / AttnRes 前向里散布的
"这里是 DTensor" 假设(那些 `_to_local_if_dtensor` 就是证据)。

### 当前 spmd_types 的可用范围

| 配置 | 状态 |
|---|---|
| CP | ✅ 与 partial_dtensor 逐位相同 |
| EP + PP + CP | ✅ 逐位相同 |
| **TP** | ❌ rowwise 部分和从未归约,grad_norm 1.36 对 3.24 |

TP 那条的直接原因已定位(87 个声明缺边界),但**修法就是这次迁移本身**。

### 建议

拆成可验证的切片,每片跑 58 格。不要在命令式计划还在时补边界 —— 每次都会在另一个后端上引入回归。

## 二、四个轴分支与 PR body 数字

`k3_pr_classified` / `k3_pr_tp_clean` / `k3_pr_ep_clean` / `k3_pr_pp_clean` **全部不含今天的修复**,
带着:

* rank 1 读错 embedding 行(前向错误,08-14 至今);
* TP grad_norm 膨胀 5.6 倍。

`k3_pr_tp_clean` 最严重 —— 它就是"张量并行"那个 PR,而它交付的 TP 实现有前向错误。

### 为什么不能只同步文件

修复**跨两层**,而层与轴的边界不重合:

| 层 | 文件 | 在轴分支上 |
|---|---|---|
| 模型层(切分脚本明写属 PR-4025) | `model.py`、`attn_res_model.py`、`sharding.py`、测试 | 五支同一份 |
| parallelize 层 | `parallelize.py`、`multimodal_model.py` | **按轴裁过,五种版本** |

试过同步模型层四个文件,仍有 8 个测试失败,因为它们依赖 parallelize 层今天的改动。

### 建议

**等 4025 合并后按 `cut_diffs.sh` 的分组一次性重切**,而不是往旧分支补文件。分组是脚本化可复现的。
重切后 PR body 里的行数、文件数需要重算 —— 那些是 reviewer 会核对的数字。

**在重切之前,四支都不能发。**
