Every published parallelism matrix so far is full-parameter, so none of them say
anything about the configuration the 48B post-training leg actually runs in. This
is the same eighteen cells under LoRA.

Possible without inventing anything: `kimi_k3_debugmodel_report_arch` is already
multimodal (MoonViT + backbone), so the LoRA flavor differs from it in exactly one
field, `lora_rank = 8`. That makes any per-cell difference attributable to the
adapter path rather than to the model. Expressibility is inherited too -- 4
attention heads and 13 layers, so `tp8` / `cp8` / `tp4 x cp4` / `pp8 x vp4` remain
not expressible, and the five max-degree cells are `ep8 x fsdp8`, `pp4`, `pp8`,
`tp4`, `cp4`.

Flavor: `kimi_k3_debugmodel_report_arch_lora`. Seed 42, `--debug.deterministic`,
global batch 8, `local_batch_size 1` so gradient accumulation is on, 10 steps,
every cell loading the same step-0 checkpoint written with
`--checkpoint.create_seed_checkpoint`. Eager.

## What this does and does not establish

It establishes that all eighteen parallelism configurations RUN under LoRA and stay
in the same numerical band -- which was not known, since LoRA had only ever been
exercised under pure FSDP and, later, the eleven-leg per-parameter probe.

It does **not** replace that per-parameter probe. A matrix of losses agreeing to
0.0146 cannot see a defect confined to a small share of the trainable signal; the
`o_proj` defect fixed on 2026-08-07 was worth 2.9e-02 in step-1 loss at tp2 and
would have sat inside this band. `LORA_PARALLELISM_MATRIX_2026-08-02.md` is the
instrument that catches those, and its PP and CP deviations are open independently
of this table.

One collector caveat, because this project has lost a matrix to one before:
`run_maxdeg.sh`'s printed preview takes `head -3` of the loss lines, which on a
cell where every rank logs a positive loss (`ep8 x fsdp8`, `tp4`, `cp4`) shows
three RANKS' step-1 line rather than three steps -- it reads as a stuck loss and is
not. Its PASS check dedups by step number and is correct; only the preview
misleads. The per-step values above were re-extracted rather than read off it.
