# Where the CP cells' step-1 loss difference comes from (2026-09-06)

cp2 reads 12.53972 at step 1 against dp1's 12.52977 (same samples: dp = 1, the sequence sharded
over cp; the four MLA kernels all read 12.53972), cp8 12.54963. Not the loss normalisation (the
trainer divides by the dp x cp global valid-token count), not the packing (the trainer's 2 x cp
rule is a divisibility check, the micro-batch stays 256 tokens), not document boundaries (on the
flex flavor the KDA layers get `cu_seqlens=None` on both paths). Upstream's validation refuses CP
kernels at cp = 1, so the kernels could not be isolated that way (`rebase_main_cp_k1.sh`).

## The stream, layer by layer (`cp_layer_probe.sh`, `cmp_cp_layers.py`)

Tree `/tmp/wt_cplayer` = `edc4cd71b` + the registry alias + a dump hack (the stream after the
embedding and after every layer, plus forward hooks on `layers.0/1.delta_attention` and
`layers.3.attention`, first micro-batch of step 1, every rank). dp1 on one GPU, cp2 on two; rank r
of cp2 holds tokens [128r, 128r + 128) of dp1's 256; the tokens match.

| point | rank 0 vs dp1 | rank 1 vs dp1 |
| --- | --- | --- |
| embedding output | bitwise | bitwise |
| `layers.0.delta_attention` input | bitwise | bitwise |
| `layers.0.delta_attention` output | relative 3.2e-3, 49% of elements differ, 66% of those within 1 bf16 ulp, largest 2.4e-4 | 3.4e-3, largest 4.9e-4 |
| stream after layer 0 | 6.1e-3 (largest 9.8e-3) | 6.1e-3 |
| stream after layer 1 | 6.8e-2 (largest 0.96) | 6.5e-2 |
| `layers.3.attention` input | 5.4e-2 (largest 1.6) | 4.5e-2 |
| stream after layer 23 | 6.3e-1 | 6.0e-1 |

So the first KDA layer's output under KCP (Attention Gym's context-parallel delta rule: chunk scan
with the state handed rank to rank, the conv history from the previous rank) differs from the
single-sequence kernel's output at bf16 accumulation level on bitwise-identical inputs -- on rank 0,
which has no predecessor, as much as on rank 1, so it is the kernel's own arithmetic, not the
handoff -- and layer 0's MoE router at random init flips on it: the stream is 6.5% off by layer 1,
5% at layer 3's input with elements off by O(1), 60% at the head, 1e-2 in the loss. The same
amplification as EP on / off on the declarations PR (1.4% of gradient elements change sign at step
1 with the same samples) and as the compile-cache floor. A trained router does not flip on 3e-3.

(a small offline check; the inputs and the seed weights are on disk).
