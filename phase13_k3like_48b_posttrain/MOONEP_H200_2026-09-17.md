## 10:20Z: audit of the fused-transport head (`904473aef` from the CPU box) and what unblocked it

- Lint on `904473aef` (scoped pre-commit on the six changed files): flake8 E704 x5 (the table backend protocol's one-line `def ...: ...` stubs), a missing final newline in `moon_ep_experts.py`, ufmt reflows in the experts module and the CPU double, and pyrefly's missing-attribute on `self._buffer._require_ctx()` (`_buffer` is None before `wire_meshes`); the hook also dropped four `# pyrefly: ignore[bad-override]` lines it now reports unused. All folded into `3c458bdf1` (author QIU023, no trailers, pushed fast-forward to `k3_moonep_seam`; PR 4751 head): ufmt's layout, the newline, and a `RuntimeError("MoonEP dispatcher used before wire_meshes(); no buffer")` guard in `grad_reduce_handles` (the same refusal `dispatch` gives). After it flake8, ufmt, end-of-file, codespell, pydoclint pass; pyrefly reports only the box's `torch_checkpointing` / `renderer` missing-import environment errors, none in the branch's files. CPU tests: 17 passed here (`test_kimi_k3_moon_ep_dispatcher`, `test_ep_token_dispatcher_capacity`, `test_inference_moe`), 11 passed 1 skipped on the box.
- Code read (`moon_ep_experts.py` 338 lines, the dispatcher and `moe.py` diffs). Consistent with the doc: per-projection `[P + B]` bf16 rows on every owner through `create_nvl_single_owner_tensor` (`_MappedRows`), `launch_prefetch` per owner with chunk-rebased ids, fp32 `[E, in, out]` grad tables plus `create_nvl_dist_tensor([B, in, out])` reduce buffers viewed `[R, B, in, out]`, `launch_grad_reduce` with the four barrier handles read once in `grad_reduce_handles`, the compacted `cu_seqlens` (`cat(cu[lo:hi], cu[E:])`) pinned by two `torch._assert_async` tripwires, two `dist.barrier` per MoE layer per step and no host sync. The autograd Function's argument order matches its backward's return order; `to_local()` on the DTensor parameters keeps the gradient path. Three things for the body or a follow-up, none a blocker for the tables:
  - The fp32 grad table is `torch.zeros(E, in, out)` per projection per rank (`alloc_grad_rows`), a physical row for every expert again, only the rank's span written. At the released shape (E, latent 3584, expert hidden 3072) that is the same 124 GiB per MoE layer per rank the 09-17 audit charged the copy version with; the kernel addresses by global expert id, so the fix is an allocation whose other spans are not physical (MoonEP's own `create_nvl_dist_tensor` gives exactly that range) or a kernel entry that takes the span. Debug shapes do not feel it.
  - The tables are per-module state refreshed in forward and read again by the backward recompute, so a forward of a later micro-batch must not run before the backward of an earlier one on the same module: fine for the sequential schedule the tables use, not for pipeline schedules that interleave (MoonEP with PP is outside the PR's claims; say so in Limitations).
  - `buffer._require_ctx()` is the one private MoonEP access (the doc names it and the upstream ask).
- cutlass-dsl 4.6.0 blocker, resolved by a one-line MoonEP-side patch. The K3 path's first backward on the fused head died in `launch_grad_reduce` with `AttributeError: module 'cutlass.cute' has no attribute 'make_fragment'` (the MLIR "requires a Location" text of MoonEP's own test on 4.6.0 was this AttributeError surfacing through the DSL tracer). cutlass-dsl 4.6 renamed the register-fragment constructor; `moonep/grad_reduce.py:295` `cute.make_fragment((H_PER,), Float32)` becomes `cute.make_rmem_tensor((H_PER,), Float32)` (`matrix_scripts/moonep_onbox/h200/moonep_grad_reduce_cutlass46.patch`, applied in the box's MoonEP checkout). With it on 4.6.0: `test_grad_reduce` 12 passed, `test_e2e` 1 passed, so all six MoonEP suites pass on the version Attention Gym's KDA needs. A static-stride rewrite of the host layouts (tried first) changed nothing and was reverted. Upstream ask for MoonEP: the rename.
