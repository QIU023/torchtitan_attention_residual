# MoonEP smoke on 4 x H200 (217.18.55.111), 2026-09-17

Takes over the MoonEP validation the PR body (`Raising_PRs/PR_K3_PARALLELISM/PR_BODY_MOONEP.md`, draft #4751, head `a706a881d` on main `b21f7d43e`) could not run on the earlier boxes: the 2 x RTX 5060 Ti (no NVSwitch), the 4 x H100 SXM of 2026-09-15 (direct NVLinks, multicast attribute 0) and the 2 x H100 NVL of 2026-08-28 (host GPUs 0 and 5, no NVLink).

## The plan being executed (from the PR body, "To run on 2 x H100 SXM")

1. `moonep_multicast_probe.py` first: every GPU must read `CU_DEVICE_ATTRIBUTE_MULTICAST_SUPPORTED = 1` and `_SymmetricMemory.has_multicast_support = True`.
2. MoonEP's own tests (`test_planning`, `test_dispatch`, `test_combine`, `test_e2e`, `test_grad_reduce`, `test_prefetch`) under torchrun, 2 ranks, then 4.
3. The Kimi K3 debug model, `kimi_k3_debugmodel_moonep` (a local flavor patch, `matrix_scripts/moonep_onbox/0002-kimi_k3-moonep-debug-flavor-a706a881d.patch`; the flavor rule keeps backend-selection flavors off the PR branch), ep2 x fsdp2 for 3 steps, next to the standard dispatcher on the same seed and one warm inductor cache (`mx3_backend` protocol: seed checkpoint, warm pass, measure pass, 10 steps, 8192 tokens per step in 256-token micro-batches per dp rank); a repeated standard cell as the noise-floor row; ep4 x fsdp4 the same way.
4. The per-parameter gradient comparison against the standard dispatcher from the same seed checkpoint (`ep_backend_probe/grad_probe.py`, one micro-batch forward and backward, `grad_diff.py`).
5. A forced-hot routing run that populates a prefetch slot: `moonep_onbox/h200/moonep_hot_probe.py`, the CPU unit test of the branch (`test_moonep_unit_matches_dense_reference_with_duplicated_experts`) rewritten for real GPUs and the real package: `MoonEPTokenDispatcher` + `MoonEPGroupedExperts` + `MoonEPTableBackendNVLink` on an EP mesh, every token routed to experts 0..K-1 (all home on rank 0, so the other ranks' slots must fill), `plan.experts_to_copy` read back, outputs and gradients against a dense fp32 reference on the gathered tokens; then a uniform routing for contrast. E=32, K=4, S=256, D=512, F=384 (the debug model's MoE shape).

Driver: `moonep_onbox/h200/run_all.sh` (cpu tests of the branch, self-tests np2, hot probe np2, matrix, grad probe np2, self-tests np4, hot probe np4, grad probe np4); results in `/workspace/results/` on the box, summary in `summary.txt`.

## The box

4 x H200 (143 GB), driver 595.58.03 (CUDA 13.2), every pair `NV18`, `nvidia-smi -q` Fabric State Completed / Status Success; 112 cores, 3 TB RAM, 683 GB free. Multicast probe: all four GPUs `multicast_attr=1 torch_symm_mem_multicast=True`. A plain Ubuntu 22.04 container with miniconda only: no torch, nvcc 12.6 (`/usr/local/cuda-12.6`), no NVIDIA apt repo needed.

## Environment decisions

- torch `2.15.0.dev20260906+cu126` with torchvision `0.30.0.dev20260906+cu126` (the two must share a date; the 0907 torch has no torchvision partner, which is what the first install tripped on), in a uv venv `/workspace/venv_k3` (Python 3.12; `conda create` silently produced no env, and the deps then landed in base with a PyPI torch 2.11 cu130, which is what the first MoonEP build's "detected CUDA 12.6 mismatches 13.0" meant). cu126 was chosen over installing a CUDA 13.0 toolkit because the box's nvcc is 12.6 and Hopper needs nothing newer; the tree on the 5060 box runs the 0906 nightly (cu130) too.
- Tree `/workspace/tt_moonep` = fork `k3_moonep_seam` `a706a881d` + the flavor patch (uncommitted). Requirements from `.ci/docker/requirements.txt` of that branch; Attention Gym is the same checkout the 5060 box uses (`b19162e`, upstream `meta-pytorch/attention-gym`; shipped as a tarball, installed editable with `SETUPTOOLS_SCM_PRETEND_VERSION=0.0.8` since hatch-vcs has no git metadata there) plus `apache-tvm-ffi`.
- `nvidia-cutlass-dsl==4.4.2`, MoonEP's own pin (`setup.py`); Attention Gym's `linear` extra asks for >= 4.5.0 but its KDA kernels import under 4.4.2. If a KDA kernel fails at JIT, that pin conflict is the first suspect.
- MoonEP `2bd860b` built with nvcc 12.6, `TORCH_CUDA_ARCH_LIST=9.0`, `pip install --no-build-isolation --no-deps -e .` (about 3 minutes); imports.
- Two pitfalls of the take-over: `pkill -f <pattern>` inside an ssh command whose later text contains the pattern kills the ssh shell itself (three dead sessions before the kills were moved into their own call); MoonEP's `NCCL_NVLS_ENABLE=0` and `MOONEP_MEM_HANDLE_TYPE=auto` from the earlier kit are kept.
