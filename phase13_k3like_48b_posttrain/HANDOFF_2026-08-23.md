## 二、MXFP4 / MXFP8(issue 4269)

### 名字的事

**没有单独的 MXFP8 文件。** 权重 MXFP4、激活 MXFP8 在同一个 wrapper 里:

    _WEIGHT_ELEM = torch.float4_e2m1fn_x2   # MXFP4
    _ACT_ELEM    = torch.float8_e4m3fn      # MXFP8

由 `quantize_act` 开关控制。文件原名 `mxfp4_qat.py` 只说了一半,现已改名
`torchtitan/components/mx_qat.py`,函数 `apply_mx_qat`(旧名 `apply_mxfp4_qat` 保留为别名)。

### 已经解耦

原来有两处 K3 依赖,现在都是参数(`08a899f0d`):

| 原依赖 | 为什么存在 | 现在 |
|---|---|---|
| `quant_scope.quantizable_modules` | K3 released config 的量化范围(仅 routed experts) | `select_modules=` |
| `KimiDeltaAttention` | **KDA 必须跳过** —— fla 直接读 `.weight` 绕过 module forward,包装了会静默失效 | `skip_subtrees=` |

fake-quant 算术本身从来没有 K3 依赖。默认值仍 import K3 版本,所有调用点不变。

### 对 4269 的覆盖

| 里程碑 | 状态 |
|---|---|
| 1 Freeze ckpt format(字节对照 compressed-tensors) | ❌ **需官方 checkpoint,不做** |
| 2 Training primitive + STE | ✅ **spec 要的就是 fake-quant**,不是我们的缺口 |
| 3 Generic converter + 200 步 gate | ✅ **三条全过** |
| 4 Packed import / export | ⚠️ import ✅(流式,不全聚)/ **export ❌ 未实现** |
| 5 分布式验证 | ✅ 除全拓扑集群 smoke 外全部 |

Gate 3 的实测(`kimi_k3_mini_qat_mxfp4`,dp2+tp2,200 步):
无 nan/inf、loss 7.70829 -> 2.00759 单调、**optimizer 615 个 key 里 packed/scale 命中 0**。
第三条又在真有 packed 参数的 `gated_qlora_mxfp4` 上验了一次:
packed/scale 在 model state 有 14 个、**在 optimizer state 0 个**,
optimizer 里只有 210 个 LoRA adapter + AttnRes 的 alpha。

Gate 5 的三项在这轮补齐:
* **零 token 专家** —— `zero_token_expert_harness.py` 把一个专家 bias 压到 -inf,
  该专家三步全程 0 token 且训练正常(自然情况下出不来:KDA 要求 T > 64,
  8 专家 top-2 在最小可行规模下每个仍有几十个 token)
* **mixed image/text ranks** —— `mixed_rank_image_harness.py`,奇数 rank 丢 pixel_values,
  dp2/cp2 下 12/12 完成,无 watchdog(失败形态是挂起不是报错)
* **DCP resume** —— 逐位相同,强于 spec 的"容差内"

### 能不能独立发

|---|---|

### 两个 P0 子项都验证过

| 子项 | 证据 |
|---|---|
| distributed histogram aggregation | 全 gather 前置计数逐 bin 比对:**dp2 下 81920 个 bin 里 34765 个跨 rank 不同**,dp4 下 32928 个 -> 是真实聚合不是重复计数 |

`loss mesh = dp_replicate x dp_shard x cp`,**不含 tp** —— TP 下 router 的 scores 是 Replicate,
把 tp 放进聚合组会把直方图乘以 tp 度。这一条是实测的,不是从代码推的。

### 一条不能声称的

**EP 下的聚合正确性没验过。** TP 被排除的前提是"EP 关闭时 scores 是 Replicate";

但"能跑"不等于"计数对",**只验了前者**。PR 正文里已经避开这个声称。

## 四、视觉塔的声明式 TP

### 已完成:MLP

`MoonViTMLP` 成为带 `Config` 的 `Module`,两个 linear 从 `Linear.Config` 构建并携带声明,
`_apply_tp_moonvit_mlp` 里那两条 `plan[...]` 删除(`91feba654`)。
58 格 58/58 逐位相同。

**关键机制**(第六次尝试才测对):`common/linear.py` 的 `Linear.forward` 自己
`to_local()` 权重再 `F.linear`。所以**声明 `in_src`/`in_dst` 会让框架把输入提升成 DTensor,
撞上本地权重 -> `aten.mm.default got mixed`**。core 的 `colwise_config` / `rowwise_config`
把两者都留 `None` 正是为此。**只声明权重切分和输出布局。**

### 实测基线(迁移必须复现)

`kimi_k3_debugmodel_report_arch`,dp2+tp2,mesh 两维 (fsdp, tp):

| 参数 | tp 轴 |
|---|---|
| `mlp.fc0.weight` | `Shard(0)` |
| `mlp.fc1.weight` | `Shard(1)` |
| `wqkv` / `wo` / norms / `patch_embed` / `mm_projector` | `Replicate()` |

### 按头切分:能用,但 gate 从不执行

`shard_heads` 分支要 `num_heads % tp == 0`:

| flavor | 头数 | tp2 |
|---|---|---|
| `report_arch`(**gate 用**) | 3 | 不整除 -> 复制 |
| `mini_vl` | 4 | -> **按头切** |
| `MoonViTConfig` 默认(官方) | **12** | -> 按头切 |

**所以 58 格从未执行过这条分支。** 用 `mini_vl` 实测:`wo` 变 `Shard(1)`、`wqkv` 保持
`Replicate`,5 步训练正常;TP 透明性用"有无 TP 对照"验过 —— dp4 的 grad_norm
25.588/19.156/19.588/16.095/17.581 对 dp2+tp2 的 24.761/18.914/19.902/16.405/17.348,
差 1-3%,是初始化 RNG 消耗不同的正常量级,**不是词表那种 5.6 倍膨胀**。

### 未完成:拆 wqkv

`wqkv` 是一个融合 `nn.Linear`,输出 `[3, A, K]`(3 在最外),前向里 `.view` 后 `unbind`。
core 的 `VisionAttention` 用独立的 `wq`/`wk`/`wv`,docstring 写明理由:
"Separate q/k/v projections (**clean per-head ColwiseParallel under TP**)"。

**收益**(注意:不是"解锁 TP 切分",那已经解锁了):

* 省掉冗余的 qkv matmul —— 每个 rank 现在算全部头再丢掉别人的
* 结构与 core 一致

**代价**:released checkpoint 是融合的(`test_hf_key_map.py:159` 有
`vision_tower.encoder.blocks.3.wqkv.weight`),拆分要在 state_dict_adapter 里做映射。

**这是性能与一致性改动,不是修缺陷。** 建议独立 gate:40/58 是多模态臂。

## 六、这一轮修掉的缺陷(都在 gate 覆盖不到的地方)

| 缺陷 | 性质 |
|---|---|
| `KimiK3Model` 的 `tok_embeddings` 无声明 | **静默**:rank 读错行 + grad_norm 膨胀 5.6 倍 |
