# The 18-cell matrix, rebased on the accurate grad norm (2026-08-09)

Supersedes the reference table in `MATRIX_18_CORRECTED_2026-08-09.md`. The losses moved for one
reason: `clip_grad_norm_` now computes the total norm in float32, so the clip factor is
accurate. See `DEP_ALIGNMENT_2026-08-09.md` for the defect and
`../Raising_PRs/PR26_torchtitan_grad_norm_low_precision/` for the upstream kit.

**Step 1 is unchanged in every cell**, as it must be -- step 1 is pure forward and clipping
only affects the update that follows. Differences appear from step 2 to step 5 depending on
the cell, with max |delta| from 3e-4 to 3.4e-2 over ten steps. That is the size a 0.2-0.4%
correction to the clip factor accumulates to, and it is the new numbers that are right.

Three TP+CP cells still fail, unchanged and for the documented reason: vision TP x dynamic CP
is unimplemented, and this runner does not set `KIMI_VIT_DYNAMIC_CP=0`.

## DEP on vs off, and why they still differ here

`run_dep_cp_cells.sh` does not load a shared seed checkpoint, so the two arms still start from
different weights -- torchtitan seeds distinctly across PP groups and DEP moves the text layers
between groups. Those arms are expected to differ and do (12.02968 vs 12.04443 on
`fsdp2_pp2_cp2`); it is not a regression.

Alignment holds where it can be asked for. From a shared seed checkpoint, all three steps are
now identical between DEP off and DEP on:

```
  DEP off   step 1 loss 11.81748  grad_norm 9.9893
            step 2 loss 11.77884  grad_norm 9.1267
            step 3 loss 11.29877  grad_norm 8.6521
  DEP on    identical on all three
```

Before the fix those arms reported grad_norm 10.008054 and 9.951641 for the same gradients,
against a true float32 value of 9.989287.
