The recipe turns SPMD type checking on, and upstream's `_set_spmd_typechecking` (`torchtitan_recipes/tests/__init__.py:20-29`) then forces `activation_checkpoint = None`, so this cell runs with no AC at all. Located with the same cell, same GPUs (2, 3), seed 42, before and after the RegionAC commit (`/workspace/.smoke_int0914/acloc_0914_042543/`): `4561e66ba` runs 3 steps at 12.96 / 14.59 / 14.59 GiB; `765606d17` hits a CUDA OOM in step 1 (the earlier smoke that survived step 1 read 14.61 GiB). The GPUs were idle between the runs. Cause: with AC off, the attention-residual math now saves its fp32 intermediates; the old always-on checkpoint wrapper recomputed them even without AC. This is main's behaviour (main never had the wrapper), about +1.65 GiB per rank on this recipe, and the recipe targets B200, where it fits; only the local 16 GB smoke is affected.

Checked and rejected: putting the recipe on RegionAC. Upstream disables AC whenever type checking is on, and forcing `activation-checkpoint:region` onto this recipe fails in forward with `SpmdTypeError: args[0] missing axis default_pg` inside torch_remat's `_unwrap_and_snapshot_inputs` (`/workspace/.smoke_int0914/region_0914_043245/`), the same incompatibility upstream avoids by turning AC off. Local 5060 smokes run this cell at 1024 tokens instead (result below).
