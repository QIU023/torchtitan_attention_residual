## 2. Main's CP contract for Kimi K3 (tree `45ed0e3c1`)

- `ContextParallelTransform(inner_attention={config type: CP backend}, exclude_fqn_prefixes=(...))` (`torchtitan/config/transform/context_parallel.py:21-68`), applied through `apply_transforms`. The two K3 recipes (`torchtitan_recipes/tests/b200.py:71-124`): all-gather KV = `{FlexInnerAttention.Config: KVAllGatherCPFlexInnerAttention, InnerKDA.Config: ContextParallelInnerKDA}` with `load_balancer_type="headtail"`; Ulysses = `UlyssesCPFlexInnerAttention` with `None`; both exclude `vision_encoder`. `validate_context_parallel` (`config/validation.py:20-85`): one CP backend type per model; Ulysses needs balancer `None` and heads divisible by `tp * cp`. The KDA kernel takes `None` or `"headtail"` (`kimi_k3/cp_kda.py:56-60`). "K3's CP needs contiguous shards" is true for Ulysses only.
- `prepare_context_parallel_batch(input_dict, *, input_shardings, cp_mesh, load_balancer_config, ptrr_mask_key=None)` (`distributed/context_parallel/api.py:242-263`) shards in place every input whose CP axis is `Shard` (`api.py:29-40`), positions included (each rank gets its slice of the global positions, not renumbered); metadata is left to the backends (`api.py:205-240`).
- Layouts: `decoder_input_sharding()` (`models/common/decoder_sharding.py:113-124`) declares `input`, `positions`, `padding_mask` as `(tokens,)` partitioned `(DP, CP)`: the folded `[T]` stream is the decoder contract on main, not a K3 trait; no `folded_token_stream` attribute exists in the tree.
- `preprocess_inputs` (`protocols/model.py:39-69`; `models/common/decoder.py:304-351`; `kimi_k3/model.py:556-625`) takes the batch with `labels` (mandatory, popped), `positions`, optional `padding_mask`, multimodal keys, plus `parallel_dims`, `parallelism`, `max_num_documents`, `max_context_length`; builds the masks from positions (K3: the dict `{"quadratic_attention": BlockMask | VarlenMetadata | None, "kda": VarlenMetadata}`, `model.py:627-659`); under CP calls `prepare_context_parallel_batch` and then `_prepare_context_parallel_metadata` (`decoder.py:354-375`), which per backend type runs `cp_shard_metadata`: all-gather KV shards every `BlockMask` on the query dim (`cp_attention.py:80-134`); Ulysses is a no-op (`:166-179`); KDA reads the global document offsets from `attention_masks["kda"].cu_seq_q` and writes `input_dict["kda_cp_routing"]` (`cp_kda.py:104-141`, multi-document by construction, needs `T % cp` or `T % (2 cp) == 0`, `cp_kda.py:61-65`); then `annotate_input_spmd_types` (every tensor in the dict must have a layout, `spmd_types.py:238-250`); returns `(inputs, labels, extra_kwargs)`.
- The model returns `[T_local, V]` sharded on tokens (`kimi_k3/model.py:970-1065`); a non-head PP stage returns `(h_TD, block_residual_TND)`, token-sharded like the hidden states. titan's trainer never gathers: the loss is computed on the rank-local shard, typed `{"dp": Partial, "cp": Partial}`, divided by `global_valid_tokens` summed over the `batch` mesh, and the CP partial is closed by FSDP's reduction over `dp_shard x cp` with `gradient_divide_factor = 1.0` (`trainer.py:796-841`, `components/loss.py:245-300`, `distributed/fsdp.py:83-97, 383`). There is no torch CP context manager; `train_context` is the SPMD mesh plus optional typechecking.
- `parallelize_kimi_k3` builds `_cp_group_all` / `_cp_subgroups` under CP (`parallelize.py:116-127`), a world-wide collective every rank runs; a text-only batch never touches the vision bank (`model.py:580-604`).
- Main ships `cu_seqlens_from_positions(positions, num_tokens)` (`kimi_k3/kda.py:39-59`) with an in-tree comment naming verl's rmpad micro-batches; the engine's private copy (`:1287-1304`) duplicates it.

## 3. The port

A. Construction: after `Trainer.Config` is built (`:367-383`) and before `Trainer(config)`, when `context_parallel_size > 1`, `apply_transforms(config, [ContextParallelTransform(inner_attention=mapping, exclude_fqn_prefixes=("vision_encoder",))])`. The mapping is derived by traversing the model config for `FlexInnerAttention.Config` / `VarlenInnerAttention.Config` / `InnerKDA.Config`, not by model name; the backend choice (all-gather KV or Ulysses) is a new engine config field; the balancer is `None` iff the chosen backend subclasses `UlyssesCPInnerAttention`, else the configured value (mirrors `validation.py:63-70`). One `ParallelDims`: the trainer's, so the balancer's `get_mesh("cp")` and the model's `spmd_mesh_group(CP)` are the same groups.

B. Input path: fold to `[T]` unconditionally at the top of `prepare_model_inputs` (main's contract) and unfold once in `_finish_pred` / the bridge; keep `ulysses_pad` (main's CP has no padding step; multiple = `cp` or `2 cp`, times 128 when a flex config remains, lcm with tp); pass a `padding_mask` for the pad tail (main's varlen metadata takes it, `models/common/attention.py:612-641`) or keep the position renumbering; drop verl's mask builder on the CP path; call `self.module[0].preprocess_inputs({"input", "labels", "positions", "padding_mask"}, parallel_dims=trainer's, parallelism=config.parallelism, max_num_documents=None, max_context_length=None)`, which replaces the positions bridge, the mask pop, both shard call sites, the `cu_seqlens` plumbing, the refusal and the manual mask rebuild; keep `labels_full` for the post-gather loss and pass the real labels in (the pop is unconditional). Nothing else goes in the dict (any extra tensor fails the layout assert).

C. Output path: unchanged in shape. Two corrections: contiguous shards only in v1 (head-tail's gathered order is permuted, `cp_kda.py:41-51`; the refusal says so), and the CP gather's `grad_scaler=True` (`:718-721`) is checked with a 2-rank CPU gradient test against titan's rule (FSDP reduces over `dp_shard x cp` with factor 1; verl re-enables division by `dp_size` without cp, `utils.py:181-197`), the same class as the TP finding of `a3661ae3`.

D. The refusal goes: main's KDA CP takes packed multi-document streams; the surviving constraint is `T % cp == 0` (contiguous), which `ulysses_pad` provides. The non-CP flex path can use main's `cu_seqlens_from_positions`.

E. Pipeline bridge: `preprocess_inputs` runs per micro-batch on every stage (each builds its own masks from the same positions; the vision bank is guarded by `tok_embeddings is not None`); the `extra_inputs` / `extra_kwargs` split collapses into the returned `extra_kwargs`, all of it forwarded through the schedule; the CP gather stays on the last stage in the bridge.

F. Probes replacing the string flags:

## 4. Risks

- Titan-dataloader assumptions: `preprocess_inputs` takes `max_num_documents` / `max_context_length` as arguments; the engine passes `None` (CUDA graphs are force-disabled, `:345-347`). The `NoOpDataLoader.Config.dataset` shim (`utils.py:47-51`) is vestigial on this tip (no sample-packing inspection in `kimi_k3/*.py` any more). `global_valid_tokens` and the CP loss normalisation are titan's data path, which the engine never enters, so the CP partial-loss / gradient-division question is the engine's alone.
- spmd_types: the forward needs the active mesh (`spmd_mesh_group(CP)` returns `None` without it and every CP backend raises), which `train_context` provides only for the trainer's `parallel_dims`; the engine's second `ParallelDims` may hand a different CP group to the gather. Collapse to one. Typechecking is refused under PP, so PP + CP cannot be type-checked.
- LoRA + CP: `LoRATransform.run_after = (ContextParallelTransform,)`, but the engine's LoRA arrives pre-applied inside the flavor (`LoRAConverter`); applying the CP transform afterwards inverts the order and converts inner-attention configs the LoRA pass already turned into frozen subclasses. Unvalidated, likely broken; out of this pass.
- Tests: the fork's engine tests cover no CP; titan's `tests/unit_tests/cpu/test_cp_attention.py:261-275` exercises `prepare_context_parallel_batch` + `_prepare_context_parallel_metadata` on fakes, and `tests/unit_tests/gpu/test_kimi_k3.py:188-197` asserts `kda_cp_routing`. The port-side test: CPU, gloo, cp=2, a packed two-document micro-batch through `prepare_model_inputs` and the gather, gathered logits equal to cp=1. It would have caught the dead import and the head-tail permutation.
