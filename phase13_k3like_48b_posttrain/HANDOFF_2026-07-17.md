## 1. 项目背景与人物

- **Yiqiao**：个人贡献者（IC），软件工程师，多篇 CV/ML 论文背景，即将有多台 H200 可用；此前在 8× RTX 5090（vast.ai）上开发验证。
- **核心资产**：自研 torchtitan **AttnRes（Block Attention Residual）实现 + PP cross-stage adapter**，支持预训练与后训练（含 AttnRes 跨 stage backward）。**数值正确性已多次验证，包括 8 卡 PP8×VP4。**
- **与 titan maintainer Tianyu 的历史**：
  - 最初 RFC 反馈：等 SOTA 模型采用该架构，期间维护 fork。
  - ~3 个月前明确拒绝了"把通用 cross-stage PP 机制单独上游"的提案：titan 风格不接受其他模型用不上的架构特化改动；**AttnRes PP adapter 应作为 K3 模型文件夹内 parallelize 的私有实现**。
  - 用户已更新旧帖回复，Tianyu 未回复；决策：**开新 RFC "Kimi K3 support in torchtitan"，7.27 权重落地前发出**，附 fork、parity 证据、分阶段计划，明写维护意愿。

## 2. 最终定位（经多轮修正后锁定）

**个人贡献者的参考实现（reference stack），不是产品。** 目标：维护一套 working 的 K3 全套训练侧 infra，让开源框架（尤其 titan）和任意下游开发者二次开发。可信度标准 = 绿的 CI + 一条命令可复现 + 干净扩展点，**不是** SLA/部署矩阵。诚实声明口径："在 48B 真权重和 K3 保真拓扑上验证，scale-out 是 config 层面的事"——绝不声称亲自验证过 2.8T。

三个被采用面：
1. **titan 上游面**（所有权主张所在）：`torchtitan/models/kimi_k3/` 文件夹达到收录标准——debugmodel CI、并行 parity、smoke flavor 收敛曲线 + MFU 进 README、state_dict_adapter，目录遵循 qwen3_5 模板。只需预训练侧证据。
2. **veRL recipe 面**（后训练）：48B + AttnRes 的 SFT/GRPO 一条命令跑通；LoRA 与全参各一个 config；跨引擎 logprob parity 脚本；接 veRL 自带 IS 校正开关并写进文档。
3. **自己的仓库（集成枢纽）**：KD 脚本、provisional 2.8T flavor、EP@896 缩维 smoke、对 titan/veRL 的版本 pin；quickstart 按 ≤8 卡写，目标"随机开发者 30 分钟单节点跑起 downscale K3"。

维护姿态本身是采用决策的一部分（pin 版本、issue 模板、CHANGELOG、跟进上游破坏性变更）——RFC 里让持续维护 fork 的历史可见。

## 3. K3 公开信息汇总（截至 2026-07-17，tech report 未出）

- 2.8T 总参（社区口径 A50B 激活），**1M 上下文（1,048,576）**，原生视觉，always-on thinking；2026-07-16 发布，权重与报告 **7.27 前放出**。
- 架构组件（blog 点名、无公式）：**KDA**（沿用 Kimi Linear 的线性注意力基础，1M 上下文 decode 至多 6.3×）；**AttnRes**（α 门控、沿深度选择性检索而非均匀累加；~25% 训练效率提升、<2% 额外成本）；**Stable LatentMoE**（896 专家激活 16，含 shared+routed）；**Quantile Balancing**（从 router 分数分位数直接导出专家分配，去掉启发式更新和敏感超参）；**Per-Head Muon**（按注意力头独立优化）；**SiTU**（Sigmoid Tanh Unit 激活）；**Gated MLA**。整体对 K2 约 2.5× scaling efficiency。
- 训练/推理侧：SFT 起 QAT（**MXFP4 权重 + MXFP8 激活**）；全平衡 EP 训练（静态 shape、关键路径无 host 同步）；推荐 64+ 加速器 supernode 部署；**KDA prefix cache 实现由 Moonshot 贡献给 vLLM，随模型发布**（vLLM 0.23 已见 KDA conv-state 统一、gate/cumsum 融合等铺垫）。
- API 定价公开口径 $0.30/$3.00/$15.00 每百万 token。
- **盯 vLLM PR 队列**：官方 K3 模型类落地时会暴露 config 真值（层比、维度、LatentMoE 结构），可能早于 7.27 报告。

## 4. Kimi Linear → K3 差异表（含 48B 权重兼容性）

| 模块 | Kimi Linear 48B-A3B | K3 | 兼容 48B 权重？ |
|---|---|---|---|
| 骨干 | KDA:MLA 3:1 逐层混合 | KDA + 新增 AttnRes；比例未公布 | ✅ α 零初始化 |
| KDA 本体 | gated delta rule 精化版，开源 kernel + vLLM 集成 | 定位为沿用基础，有无微调未知 | ✅（大概率不动） |
| Full-attn 层 | MLA（NoPE、无门控） | Gated MLA | ⚠️ 门 near-identity 初始化 |
| MoE | K2 谱系常规 MoE | Stable LatentMoE 896/16 | ❌ 结构不同 |
| 负载均衡 | DeepSeek 式 bias 启发式 | Quantile Balancing | ✅ 训练器侧 |
| 激活函数 | SwiGLU | SiTU | ❌ 毁权重 |
| 优化器 | Muon | Per-Head Muon | ✅ 优化器侧 |
| 量化 | 无 QAT | SFT 起 MXFP4/MXFP8 QAT | ⚠️ H200 无 MX 硬件，用 FP8 平替 |
| 模态/上下文 | 纯文本 | 原生视觉、1M | — |

**路线含义**：❌ 项做成默认关闭的 config flag（属 downscale 预训练/7.27 后）；路线 A 模型严格 = Kimi Linear 48B + AttnRes(α=0) [+ 可选 Gated MLA 门 near-identity]，step 0 与原 checkpoint 数值等价，是 PP adapter 正确性的最干净锚点。✅ 三项（QB、Per-Head Muon、AttnRes）可在训练器直接开。

## 5. 已达成的关键技术结论

### 5.1 推理是否需要 cross-PP-stage cache
- 训练态 cache 有两职责：**跨段运输**早层 attn 输出 + **为 backward 保留**至对应 microbatch 反向到达。推理无 backward，retention 消失。
- 若 AttnRes 是 **position-wise**（blog 措辞高度暗示，DenseFormer/DWA 一族）：decode 每步只需当前 token 的早层张量，随激活沿 PP 流动、用完即弃；历史 token 影响已烘焙进后层 KV/KDA state。**推理不需要持久 cache，只需扩展 per-token 的 stage 间 payload（vLLM 即 IntermediateTensors）。** prefix cache 恢复只恢复 KV 即可。
- 仅当后层对早层输出的**整个序列**做注意力（cross-layer KV 共享 / YOCO 类）才需真正跨段历史缓存——公开信息不支持，但接口留口子到 7.27。
- 勿混淆：KDA 的 prefix caching 挑战是线性态快照问题（Moonshot 已给 vLLM 提实现），与 AttnRes 无关。

### 5.2 KDA 与 CP
- Ring attention 依赖 softmax 的 online-softmax 可合并性，**不适用于线性注意力**。线性注意力序列并行的正确原语是**状态传递/scan**（LASP/LASP-2 路数）：各 CP rank 独立算 intra-chunk，inter-chunk 校正靠上游传来的小状态 S（每头 d_k×d_v）。FLA 系 kernel 是单卡 chunkwise 写法，跨卡 hand-off + 反向逆 scan 是独立工程 → "KDA kernel 不支持 CP" 属预期。
- 混合架构下：1M 训练需要序列切分，但 ring/zigzag（或 Ulysses）只作用于 full-attn(MLA) 层；KDA 层走状态传递或 Ulysses 式按 head 切。具体方案等 7.27。
- titan 的 qwen3_5（同为线性混合架构）parallelize 里 CP 仅一处多模态约束注释——**线性层 CP 在 titan 也是空白，是可占的坑**；当前项目将 CP 明确列为 non-goal / future work 写进 RFC。

### 5.3 torchtitan 现状与接入模式（2026-07 主分支实查）
- Roster：llama3（1B–405B）、deepseek_v3（**16B**/236B/671B——大架构小 flavor 的先例）、qwen3（0.6B–32B 稠密 + 30B-A3B/235B-A22B）、**qwen3_5**（0.8B–27B + 35B-A3B/122B-A10B/397B-A17B；**75% GatedDeltaNet + 25% full attn 混合，VLM**）、gpt_oss（20B/120B）、flux。experiments：**rl**（titan 模型定义 + vLLM rollout 的 GRPO，vllm_wrapper 双端共享定义、bitwise parity 口径，Monarch 编排、TorchStore 权重同步）、forge、torchft、transformers_modeling_backend、graph_trainer。
- 接入方式：模型目录含 model.py（纯 nn.Module）/ config_registry.py / parallelize.py / state_dict_adapter.py，`model_registry(flavor) -> ModelSpec(name, flavor, model, parallelize_fn, pipelining_fn=pipeline_llm, state_dict_adapter)`；公共模块在 models/common。
- **qwen3_5 是 KDA 接入的直接模板**：`fla.ops.gated_delta_rule`（chunk + fused_recurrent）经无状态 kernel dispatch 模块（DTensor→local）+ torch-native O(L) 参考实现。FLA 库自 Kimi Linear 起有 `fla.ops.kda` 同套接口。

### 5.4 PP adapter 在 AttnRes + LoRA 后训练 5D 并行中的作用（重要，防误判）
- **LoRA 不豁免跨段 backward**：冻结底座 ≠ 冻结梯度流。早段 LoRA/α 的梯度依赖 dL/d(激活) 从尾段回传，AttnRes skip 边是 autograd 真实路径——早层 attn 输出梯度 = 顺序分量 + 所有后段消费层经 α 回传的 skip 分量之和。adapter 不路由 skip 分量 → **silently wrong 梯度**（不报错）。
- LoRA 省掉权重梯度/优化器态后用户会加大 microbatch/seq → adapter 的跨段激活 retention 在显存占比**上升**；retention 语义由激活决定，与权重可训性无关。
- 与其余维度：DP/FSDP、EP 正交；TP-SP 需约定残差流跨段按 SP 分片传输（省 1/TP 通信）；**position-wise AttnRes 对 CP 透明**（各 rank 传自己分片给下一段对应 rank，零额外集合通信）；总代价 = PP P2P 流量 ×(1+流数)。VP 已验证。
- **LoRA 特化机会**：若"只训 α + 后段 LoRA"（早段无可训参数），早段 backward 含 skip 梯度可整段剪掉 → 给 adapter 加 `first_trainable_stage` 开关做部分反向截断。
- 定位诚实话：48B LoRA 单节点 FSDP 即可跑；48B 上 PP×LoRA 的意义是**组合正确性 parity 证据**；该组合真正不可替代在 2.8T（4bit 底座 ~1.4TB，前向必须 PP+EP 摆放）——此论证即 RFC "为什么该 adapter 值得存在"一节素材。

### 5.5 规模与生态判断
- Moonshot 旗舰不出 size ladder（K2 仅 1T 一档；Kimi Linear 是研究线）→ **官方 downscale 大概率永不存在**；2.8T 现实后训练 = 全参（64+ 加速器级）或 LoRA-on-quantized（2–4 个 8 卡 H200/B200 节点）→ 社区 downscale + KD 是真空地带。
- 2.8T 客户 rollout 侧由 Moonshot 官方 vLLM 贡献解决（K3 类 + KDA prefix cache + AttnRes 处理）→ 自研 vLLM AttnRes 补丁仅服务 48B POC，够用即止；官方 vLLM K3 类接口一公开即冻结权重同步层的张量命名。

## 6. Seq-KD 结论
- **价值定位**：不是补预训练（KD 教不会 undertrained base 世界知识），而是让 smoke 预训练的 downscale 模型 **RL-able**（否则 GRPO reward 全零）+ 值得下载。
- 体量：主体 100K–500K 条指令/推理轨迹（参考 R1-Distill ~80 万条），大头用开源蒸馏集（OpenThoughts 类）免费填充；**K3 API 只买 K3 特有部分**——1–5 万条 agentic/工具/长程编码轨迹（~0.5–2B 输出 token，按公开定价数千至三万美元级）。
- 注意：先查 Moonshot API ToS 输出训练条款；7.27 后可租 ~16×H200 自托管 MXFP4 权重做 **logit 级白盒 KD**（样本效率远高），API 采数够冒烟即可，勿一次买满。
- 当前优先级：KD/downscale 产品线整体排在 titan 文件夹 + veRL recipe 收口之后。

## 7. Gap 清单（IC 参考实现口径）

**Trainer（titan）侧**：KDA 前反向 ✅（魔改 Kimi Linear 栈已有）；AttnRes+PP adapter ✅（含 backward、PP8×VP4）；常规 MoE+EP ✅（models/common）；Gated MLA flag ⚠️ 小活；**Kimi Linear HF state_dict_adapter ❌ 必补**（48B 真权重入口）；**DCP 存/取/PP 度重切分（含 AttnRes 额外流）❌ 必验**；Muon/Per-Head Muon ⚠️（titan 现状待确认，Per-Head 自写、权重兼容）；CP 长上下文 ❌ declared non-goal。

**veRL 侧**：titan 模型接 veRL trainer backend 🔧（主体工程，veRL 原生仅 FSDP/Megatron）；vLLM Kimi Linear rollout ✅ 上游现成；vLLM α payload 补丁 ❌ 小；**权重同步/重切分（trainer PP×TP×EP → vLLM，含 α；先做 LoRA-only 同步路径）❌ 最难**；跨引擎 logprob parity ⚠️（有 PP parity，缺跨引擎层）；SFT 管线（packing、多轮/工具 mask）⚠️；GRPO recipe ✅ veRL 现成；KD 管线 ❌ 后置；LoRA 路径 ❌（作为低门槛 config，非战略项）。

**Blocked on 7.27（只留占位）**：α 精确公式、LatentMoE 分解、SiTU 公式、KDA:MLA 比例、MLA 是否保留 NoPE、Per-Head Muon 细节、官方权重映射收尾、MXFP4 QAT。
