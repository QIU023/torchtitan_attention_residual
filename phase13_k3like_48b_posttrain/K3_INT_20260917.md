## 2026-09-18: tonight's aggregation and initialisation, and what they cost

`42691735c` on `k3_on_4025`. Two changes carried over from the upstream-bound work, plus the one test they invalidated.

The attention residual aggregation is now `_AttentionResidualAggregation`, an autograd Function that saves per-token statistics and references to its two inputs and recomputes the FP32 upcasts in backward. At the released shape one call goes from 1008.2 MiB of retained bytes to 0.2, and with a block checkpoint on the forward peak falls 6.3x and the backward peak 4.7x. It is registered with `register_local_autograd_function`, without which strict SPMD type checking raises.

The three residual projections in the main decoder now initialise to zero. Only the MTP block carried that before, from `76551386f`; 485, 487 and 539 were still on `trunc_normal` at std 0.02. Section 5 of the report requires zero so the depth softmax starts uniform.

**What this costs, which matters more here than on the upstream branch.** The batch-invariant path is deliberately left on the plain form. It avoids CUDA `sum` and `bmm` so the reduction schedule cannot vary between runs, which is what `experiments/rl/docs/bitwise_parity.md` depends on, and the Function's `matmul` and `softmax` would undo exactly that. So under `is_in_batch_invariant_mode()` this tree gets **no memory benefit at all**, by choice. Anyone measuring the aggregation on the RL side will see the old numbers and should.

`test_no_stack_shaped_activation_is_saved` had to change rather than pass unaltered. Its control asserted that removing the checkpoint brings the `[T, 2, D]` stack back into the saved set, which proved the checkpoint was doing the work. Nothing builds that shape now except the batch-invariant path, so the test asserts all three cases instead and keeps its original intent. The full K3 CPU suite reads 87 passed with 5 subtests, against 86 passed and 1 failed before the test was updated.
