# Finding 55: both suggested replacements are worse here, measured

Finding 55: `moonvit.py`'s per-image Python SDPA loop should become the shared
`VarlenAttention` or `FlexAttention` with a vision block mask, as the qwen3_5 vision path
does. Attempted last, per instruction. Not taken, and both branches were measured rather
than argued.

## `VarlenAttention` cannot be constructed on this box

    ModuleNotFoundError: No module named 'flash_attn'
    torch/nn/attention/_fa4.py:54 in register_flash_attention_fa4
    common/attention.py:112 in VarlenAttention.__init__

`get_cuda_flash_attention_impl()` reports `FA4` on this RTX 5060 Ti (cc 12.0), so
`VarlenAttention.__init__` calls `activate_flash_attention_impl`, which imports
`flash_attn` -- not installed. The module cannot be instantiated at all, so there is no
numerics comparison to make and no matrix cell that could run. Installing flash-attn for
SM 12.0 is a toolchain change, not a code change, and it would gate the vision path on a
dependency the rest of this model does not have.

## `FlexAttention` works, and is a REGRESSION eager

It composes correctly. Block-diagonal mask over three packed images (bounds 0/30/70/96,
4 heads, head_dim 32, bf16), against our per-image loop:

    max|diff| 7.812e-03   mean|diff| 4.183e-04

That is the scale of a different bf16 attention kernel, which is expected and would be
acceptable on its own. What rules it out is what PyTorch says when it runs:

    UserWarning: flex_attention called without torch.compile() - this will use an
    unfused implementation that materializes the full scores matrix instead of
    generating a fused kernel.

Every flavor in this repo's matrix runs **eager** (`compile.enable=False`). Compiled,
FlexAttention skips masked blocks and costs about the same work as the loop while fusing
it; uncompiled it materialises the full `L x L` scores. Our loop already costs only
`sum_i L_i^2` over packed images, which for a NaViT-packed batch is far less than
`(sum_i L_i)^2`. So adopting it eager makes the vision attention strictly worse in memory
and bandwidth -- the exact dimension the finding is about.

## Verdict

Not taken. The finding is right that the loop is duplication, and the reuse is real -- but
it is only a win under `torch.compile`, and it is unavailable in the other form on this
hardware. The honest prerequisite chain is:

1. decide whether the vision tower runs compiled (it does not today), or
2. install and validate flash-attn for SM 12.0 and use `VarlenAttention`.

Either is a bigger decision than the loop it replaces. What is NOT a reason to leave it is
"the loop is fine" -- at real scale MoonViT-V2 is 447.4M against k3mini's 80.9M text side,
and per-image Python iteration over 27 blocks is exactly the kind of overhead that stops
mattering only because this box runs a 4-layer debug tower.

## What was checked

* `get_cuda_flash_attention_impl()` -> `FA4`; `import flash_attn` -> ModuleNotFoundError.
* `VarlenMetadata` is `(cu_seq_q, cu_seq_k, max_q, max_k, cu_seq_q_host)`; our
  `cu_seqlens` already carries what it needs, so the metadata is not the obstacle.
* FlexAttention numerics and the uncompiled-materialisation warning, above.
