# veRL x torchtitan x kimi_linear SFT smoke — WORKING (2026-07-19)

First end-to-end veRL SFT of a K3-family (kimi_linear) model on the
torchtitan engine. 16 steps, 2x5090, FSDP dp_shard=2, loss 1.38 @16 on
the tiny fixture set; checkpoint saved. Env: /venv/verl (verl
0.9.0.dev0 editable from verl_src @e003163 + our
verl_kimi_linear_engine.patch, torch 2.12.0+cu130, fla-core,
tiktoken/blobfile), fork on PYTHONPATH.

## Exact command

```bash
source /venv/verl/bin/activate && cd /workspace/verl_src
export PYTHONPATH=/workspace/torchtitan_attention_residual/torchtitan:$PYTHONPATH
torchrun --nproc_per_node=2 -m verl.trainer.sft_trainer \
  engine=torchtitan optim=torchtitan \
  engine.data_parallel_shard_size=2 engine.spmd_backend=default \
  model.path=/workspace/fake_hf/kimi_linear_194m \
  model.trust_remote_code=true \
  data.train_files=/workspace/fake_hf/sft_tiny.parquet \
  data.train_batch_size=8 data.micro_batch_size_per_gpu=1 \
  data.max_length=512 data.max_token_len_per_gpu=2048 \
  trainer.total_epochs=1 'trainer.logger=[console]'
```

## Checkpoint-dir requirements discovered (feeds the 7.27 runbook)

The model dir must look like a real HF export end to end:

1. `config.json` in the OFFICIAL structure (auto_map +
   `configuration_kimi.py` + `modeling_kimi.py` copied from the 48B
   snapshot; transformers needs them to accept model_type
   kimi_linear), dims matching a registered flavor (the engine derives
   the flavor by hidden/layers/vocab).
2. Kimi tokenizer files (`tiktoken.model`, `tokenization_kimi.py`,
   `tokenizer_config.json`, `chat_template.jinja`) -> veRL data path;
   pip needs `tiktoken` + `blobfile`.
3. A `tokenizer.json` placeholder for TITAN's own tokenizer builder
   (unused by veRL's data pipeline but required at Trainer build; the
   Llama-3.1 tokenizer.json works).
4. Safetensors named `model-XXXXX-of-XXXXX.safetensors` -- titan's
   StateDictAdapter base regexes the shard number out of weight_map.

## Known constraints (tracked)

- `engine.spmd_backend=default` REQUIRED: veRL's engine default is
  spmd_types, whose mesh has no flattened "fsdp" axis; our
  parallelize.py requests "fsdp"/"batch". spmd_types support = future
  work item.
- LoRA: veRL's SFT trainer has LoRA plumbing but only the FSDP engine
  implements it; the torchtitan engine has none -> LoRA P0 trio is
  fork-side work (as HANDOFF assumed).
- 48B full-param on this box: fp32 shards + AdamW states exceed both
  32 GiB GPU and 503 GiB host; H200 leg per PLAN 3c.

The 194m fixture checkpoint is generated by exporting a random-init
flavor through KimiLinearStateDictAdapter.to_hf (see the command
history in GPU_CHECKLIST_RESULTS / this file's git log).
