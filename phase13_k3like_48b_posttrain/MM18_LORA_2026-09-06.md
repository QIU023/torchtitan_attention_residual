# The mm_lora arm on the new tree (2026-09-06)

The 54-cell gate's third arm (LoRA on the multimodal model across dp / tp / pp / cp / ep) had
never run on the new tree: `lora_review1` (8 commits on `af9b6b195`) only has dp1 / dp2 / dp2 x ep2
rows. Branch `mm18_lora_int` (fork) = `mm18_int` `40bb5bbb7` + those 8 commits (clean cherry-pick,
no file overlap with the integration) + two fixes found on the first launch:

1. **`components/lora.py`, `_lora_adapter_sharding`** (`d370ad908`): the adapter placement was
   derived only for bases declared R, S(0) or S(1) on TP; the declarations PR keeps the stream
   weights (`routed_up`, `output_res_proj`, the residual projections) **I** without sequence
   parallel, and the assert fired at the seed build (`moe.py:123` -> `lora.py:56`), the same assert
   that fails `test_experts_pack_under_the_declared_sharding` on the integration tree. Fix: a base
   that is not sharded on TP (R or I) gives its adapters its own placement. 19/19 LoRA CPU tests.
2. **`kimi_k3/pipeline_stage.py`** (`4716f8ee6`): every PP cell died at the first backward with
   `stage 0 micro-batch 0: no gradient arrived for the payload carrying its own blocks [0]`. Block
   0's entry residual is the embedding output; under LoRA the embedding is frozen and the block has
   no trainable ancestor, so the payload's metadata says `requires_grad=False`, the next stage has
   no gradient channel for it (`delta_needs_grad` reads `inputs_meta[1].requires_grad`) and sends
   None. The stage now accepts None for a payload whose own output metadata needs no gradient and
   discards the deposits for those blocks (`_collect_into(None, ...)`). 8/8 PP CPU tests. The old
   adapter forced `requires_grad_(True)` on every commit instead (`pipeline_adapter.py:628`).

Also needed: `kimi_k3_debugmodel_lora_cp2`, a run-worktree alias (uncommitted) that applies the CP
transform first and the LoRA converter second; the other order is refused because the converter
wraps every base, kernels included, into a Frozen subclass and the CP retype wants the plain type.

## The run

shared experts, `routed_down` / `routed_up`), the LoRA seed `.mx3_seeds_main33/kimi_k3_debugmodel_lora_*`,

the TP x CP cells. The pp4 cell ran before fix 2 landed and is rerun at the end.
