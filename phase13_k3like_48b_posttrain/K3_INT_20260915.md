## Fixes after the first smoke (integration commits)

- `64ec95e3b` lora: `qlora_mxfp4` stopped in parallelize with `RMSNorm.weight has no placement declared` (the old tree `57d7efbfd` fails the same way; the 09-10 tree passed). Kimi K3's MLA sharding hands one `ShardingConfig` object to `wq_a`, `q_norm`, `wkv_a` and `kv_norm`; the MXFP4 LoRA linear swapped `weight` for the packed pair inside that shared object, so `kv_norm` lost its entry (located with a parallelize probe naming the module chain). The packed linear and the packed experts now rewrite a private copy and install it after `Config.build`. 25 LoRA / QLoRA / QAT CPU tests pass.
- `9c5876776` cp transform: both K3 CP recipes stopped at step 1 with `block_mask was created for a smaller length`. `ContextParallelTransform` replaces inner attention by config type, so the MoonViT tower's `FlexInnerAttention` became the CP one too, while the tower encodes whole images on every cp rank; the K/V gather doubles the key length against the tower's own mask. PR 4639's head `e06dcbee3` run unmodified on this box (guard lift only) fails both recipes identically, so this is in the upstream PR, not the stacking. The transform takes `exclude_fqn_prefixes` and the two K3 recipes exclude `vision_encoder`. Muse Glimmer's `mm_tp2_cp2_pp2` recipe maps the same type over a tower that uses the default `FlexInnerAttention`, so it likely has the same problem (not run). Candidate upstream issue for PR 4639; not raised.
- `ae0c7372c` tests: `test_no_new_cli_options` flagged the MTP loss fields and `context_parallel_load_balancer.load_balancer_type`; PR 4639's head fails that test on the balancer option alone.
- CPU after the fixes: the CP, transform, definitions and frozen-CLI tests pass (47).

### What the GRPO smoke hit on this tree (fsdp2, GPUs 6,7, `rl` flavor)

1. `ParallelismConfig` has no `spmd_backend` any more and takes `ContextParallelLoadBalancerConfig`: engine commit `ffd1b120` passes each field in the form the tree has.
2. `init_distributed` requires BFX9 fp32 matmul emulation on compute capability >= 10.0 (main's #4484); venv_verl's torch (pinned by the vLLM build) rejects `"bfx9"`. Engine commit `c9ade89e` builds the Trainer with that step reduced to a warning when torch rejects it, so fp32 matmuls keep torch's default precision on this venv.
3. The debug export `/root/models/kimi-k3-debug-nt` predates the released A_log layout (`[H]`; the adapter since `32db09df1` reads `[1, 1, H, 1]`, as `/workspace/k3qat_mm_hf` does). The only shape difference over the 1428 keys is the 9 KDA `A_log`s. `/root/models/kimi-k3-debug-nt-rel` = the same weights with A_log reshaped, every other file a symlink; vLLM's `a_log_weight_loader` takes both layouts. The runner now defaults to `-rel`.
4. The per-layer mask lookup: the last passing GRPO runs (`verl_grpo_newtree_*.sh`) used `/tmp/wt_k3int_cp`, an older tree with uncommitted edits, where the block took one BlockMask and KDA took `cu_seqlens`. Current trees key the masks by consumer (`quadratic_attention`, `kda`) through `KimiK3Model.get_attention_masks`; the engine still passed verl's single BlockMask, so the first layer raised `TypeError: new(): invalid data type 'str'`. That error was masked: the eval context's `__exit__` offloads the model while the exception is in flight, and FSDP2 fails there because the root group (`output_res_norm`, `output_res_proj`) never left FORWARD (`reshard()` returns early for a FORWARD group with `reshard_after_forward=False`). Located with two probes on `FSDPParam.reset_sharded_param` and the group's pre/post forward counts (pre 1, post 0). Engine fix: for Kimi K3 (non-CP) the engine asks the model's own `get_attention_masks` with the `[T]` positions.
5. Not ported: K3 CP in the engine (the new tree shards CP batches through `preprocess_inputs` / `prepare_context_parallel_batch` and needs `kda_cp_routing`); the engine keeps refusing packed micro-batches under CP.
6. The runner's micro-batches came from the 09-02 script (log-prob micro-batch 8): the 163840-vocab entropy then runs out of memory on a 16 GB card at step 2. The runner now follows `verl_grpo_newtree_nd.sh` (actor, ref and rollout log-prob micro-batch 1, the synthetic reward), with param and optimizer offload kept on.
