# 并行证据的判据与方法学(2026-08-25 定稿)

这份取代之前散在各 evidence 文档里的方法学段落。三份 `*_TEXT_EVIDENCE.md` 里
2026-08-25 之前的所有数字全部作废 —— 换了上游基点(`5fecad929` -> `30eb5e502`)、
换了全局 batch、换了分支代码,不能与新表混读。

## 一、一张表 = 一次 run

一个格子只与**同一次 run 里的**格子可比:同一个 seed checkpoint、同一个全局
batch、同一份代码。跨 run 的数字不能相减。

这条不是洁癖。三次实测:

* 同 flavor 同 seed,gbs 从 2048 提到 4096,PP 的 step-2 偏差从 1.63e-3 变 8.2e-6;
* 同 flavor,rebase 跨 6 个上游提交(含 TextCollator padding),dp1 三个数不变;
* 同一个 cp2,换 run 之后 s2 从 5.8e-4 变 2.19e-3。

所以"上一轮 cp8 是 6.8e-3、这一轮是 2.66e-3"这种句子只能当**趋势提示**,不能
当结论;要下结论必须在一张表内。

## 二、只用 step-2 下断言

`step 1` 报逐位性(PP 能做到逐位相同,CP/EP 不能,这是各自机制决定的)。
**`step 2` 是唯一可判的偏差列** —— 离共同起点一个 optimizer step,还没被曲线放大。
`step 3` 和 `step 10` 只作"跑满 10 步没发散"的记录。

证据:CP 表里 `cp4` 的 s3 是 4.11e-2(全场最大),s10 是 3.20e-3(全场最小),
同一格在两步之间差一个数量级。`dp2 x cp4`(4.03e-3)比 `dp2 x cp2`(9.90e-3)更紧,
非单调。这两条都与"CP 度数越高越差"矛盾,与混沌一致。

参照范围用老树 58 格的 s2:**1.2e-4 ~ 3.2e-3**(37 个可比格)。

## 三、`dp2` 必须进表

光把 data_parallel_shard_degree 从 1 换成 2、一个并行轴都不开:

| | s1 | s2 | s3 | s10 |
|---|---|---|---|---|
| dp2 vs dp1(CP 表,gbs 16384) | 8.9e-5 | **1.20e-2** | 7.23e-2 | 3.77e-2 |
| dp2 vs dp1(PP 表,gbs 4096) | 4.8e-4 | **1.56e-2** | 3.80e-2 | 5.30e-2 |

**比任何一条并行轴自己的偏差都大。** 原因是已知的上游行为:
`torchtitan/components/data/packing.py:91` 的 TODO —— first-fit 打包发生在 DP
分片**之后**,所以不同 dp 度根本不训练同一批 token。

后果:任何 dp>1 的格子拿 dp1 当基线,量出来的主要是 dp 度变化。**每张表必须
自带同 dp 度的纯数据并行行。**

## 四、mesh 格不是单变量对照

`parallel_dims.py:281` 是 `fsdp = dp_shard * cp`。所以 `dp2 -> dp2 x cp2` 同时
改了两件事:序列切分,以及 FSDP 分片宽度(2 路 reduce-scatter 变 4 路,每 rank
持有的参数分片从 1/2 变 1/4)。

量出来的不是"CP 的贡献"。要做成单变量,基线得是 **fsdp mesh 大小相同**的纯数据
并行格(比 `dp2 x cp2` 应该用 `dp4`,不是 `dp2`)。当前表里没有这一格。

**因此 PR 正文对 mesh 格只列表,不写"这是 CP/PP 带来的偏差"这类因果断言。**

## 五、断言与闸门(`mx3.sh`)

一个从随机初始化开始训的格子,数字长得和正常结果一模一样。所以:

* 每个计量格断言日志出现 `Loading the checkpoint from`,否则标 `ASSERT-SEED-FAIL`;
* 拷完 seed 目录**数文件数**,与源不符标 `SEED-COPY-FAIL` 并跳过该格;
* 每格开跑前查可用空间,低于 20G 标 `DISK-LOW` 中止;
* `seed files=N` 记进 results.txt 头部,事后可复核。

第二、三条是 2026-08-25 加的:一个格子的 measure pass 在磁盘 89% 时 `cp -r`
静默失败,打出了完整的三个数(12.45211 / 7.47678 / 3.23224),只有断言列写着
`ASSERT-SEED-FAIL`。只看数值不看断言列,它会直接进证据表。

## 六、今晚收回的两条读数,和它们共同的成因

1. **cp8 "超出老树上限 2.1 倍"** —— gbs 8192 下 s2 = 6.8e-3。gbs 16384 下是
   2.66e-3,族内;且 cp2/cp4/cp8 = 2.19/2.63/2.66e-3 是平的,不是原来那种每翻倍
   涨 3–4 倍。据此设计的 `cp8_shard.sh`(扫每 rank 分片宽度)不必要了。
2. **`fsdp2_cp2` "出族"** —— s2 = 1.79e-2。它是拿 dp2 当基线量的,而**当时没有
   测过 dp2 自己相对 dp1 的漂移**(是 1.2e-2)。那格从来不是异常值。

共同成因:**拿一个自身漂移未测量的基线去判别一个格子。** 第三条("dp2 必须
进表")就是为了让这个错误不能再发生。

## 七、还欠的对照

* **CP 的算术地板**:PP 的偏差随 batch 增大而塌(混沌),CP 没有观察到同样的塌陷。
  但两次观测来自不同 run,不能相减。要判地板,需同一分支同一 seed 只扫 batch
  (`cp_batch_sweep.sh`,8192/16384/32768,每组 dp1+cp2+cp4)。
* **单变量 mesh 对照**:`dp4` vs `dp2 x cp2`(fsdp mesh 同为 4)。
* **PP 载体的反证**:"去掉块残差传递会怎样"的旧数字(step 3 从 7.44679 变
  9.30017)早于当前基点/batch/分支,已从 PR 正文删除,未重测。
