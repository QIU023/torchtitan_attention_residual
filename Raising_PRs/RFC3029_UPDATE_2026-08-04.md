## Draft body

### Where this stands

Since K3's release we have been building the parallelism side against the full
architecture -- KDA, Gated MLA, Stable LatentMoE, Block Attention Residuals,
and the MoonViT-V2 vision pathway. That work is complete and running, and we
are posting it now as early evidence rather than waiting for the eager
reference (#4025) to land.

Branches (fork `QIU023/torchtitan`), all currently carrying the complete
implementation; they will be sliced per-topic and rebased onto
`torchtitan/models/kimi_k3/` once the eager reference lands:

| slot | scope | branch |
|---|---|---|
| A | TP: KDA NoParallel, Gated MLA, LatentMoE placements | `k3_pr_a_tp_kda` |
| B | EP + grouped GEMM | `k3_pr_b_ep_grouped` |

### Results

Multimodal debug model, thirteen parallelism configurations, seed 42,
`--debug.deterministic`, gradient accumulation on:

| | eager | compiled |
|---|---|---|
| 3 steps | 13/13 | 10/13 |
| 10 steps | 13/13 | -- |
| 100 steps | 13/13 | -- |

The thirteen are `dp1`, `fsdp2`, `pp2`, `cp2`, `tp2`, every 3-of-4 combination
of FSDP/TP/PP/CP, and the same again with EP on. Step-1 losses span 12.0385 to
12.0797 across all thirteen, against `ln(163840) = 12.006`. Two independent
full matrix runs agree bit-for-bit on every leg.

Three qualifications, stated here rather than left for someone to find:

1. **The 100-step run overfits a smoke dataset** (12.06 -> 0.37). It shows
   thirteen configurations behaving consistently and stably over that window;
   it is not a convergence result. Real curves need a real pretraining run,
   which is queued.
2. **The three compiled failures are one upstream cause, not ours.**
   `torch._grouped_mm` rejects an operand whose contraction dimension is zero,
   which is the shape the weight-gradient form takes when an expert group is
   empty. Five-line reproduction with no model, no compile and no distributed;
   being filed against pytorch/pytorch separately. Empty groups themselves are
   fine in both modes.
3. **The model used for the matrix is the eager reference's debug
   architecture, not the report's.** One difference, which we are raising on
   that PR as a config-level question: its final layer is KDA where report
   sec 2.1 places an additional Gated MLA "ensuring that the final layer
   always performs global attention". Our own configs implement the report's
   layout; we ran the matrix on theirs deliberately, so the comparison is
   our parallelism against their model rather than two different models.

One shared-code fix already came out of running this matrix at the gradient
level: on the TP-without-EP legs (`tp2`, and every FSDP/PP/CP combination
with EP off), gradients below the routed experts came back systematically
under-reduced -- a 3.10x whole-model grad_norm gap at dp2 x tp2, invisible
in loss curves because Adam is scale-invariant. The root cause is in the
shared MoE sharding config, reproduces on unmodified deepseek_v3, and is
filed with the per-parameter evidence as #4054. The EP-on legs were never
affected.

### The one interface the PP slice touches, and who adds it: we do

Nothing to merge yet and nothing we are asking anyone to build. The eager
reference's decoder loop already threads the right pair -- `(h_BLD,
block_residual_TND)` in and out of every layer -- so the PP slice needs only
two seams: the block-residual stack is currently created inside the forward
(a stage cannot pass an incoming stack in), and the loop always runs all
layers. **Our PP PR adds both** -- an optional initial-stack argument and a
layer-range slice, returning the pair when the range stops short -- as its
first, separately reviewable commit. Stated here so the interface is on the
record before that PR opens.

TP, EP and CP need no seam at all and rebase cleanly.
