### Parallelism matrix on the eager reference's own debug config

Multimodal (MoonViT + backbone), seed 42, deterministic, gradient accumulation on. Thirteen degree-2 configurations -- single-GPU, `fsdp2`, `pp2`, `cp2`, `tp2`, every 3-of-4 combination of FSDP/TP/PP/CP, all repeated with EP -- plus max-degree cells on 8 GPUs:

| | eager | compiled |
|---|---|---|
| 3 / 10 / 100 steps | 13/13 | 10/13 (3 steps) |
| 100 steps, report architecture (final layer global) | 13/13 | 10/13 (3 steps) |

All eighteen cells were also run compiled on the report architecture: **15/18** as-is, **18/18** with the shim below. Eager on that architecture is 18/18 at 10 steps.

| max-degree cell | result |
|---|---|
| `ep8_fsdp8` (1 expert/rank) | pass, eager and compiled |
| `pp4` (uneven 13-layer split, vision tower on stage 0) | pass |
| `tp4`, `cp4` (1 head/rank) | pass |
| `pp8` | pass, after one fix (below) |

**18 of 18 attempted, on both model configurations** (eager, 10-step horizon); step-1 bands 12.0325-12.0797 vs 12.0345-12.1005 (all just above `ln(163840) = 12.006`), two independent full runs bit-for-bit identical. `tp8`/`cp8` are inexpressible on this config (4 heads), `pp8 x vp4` on 13 layers. Per-cell tables, scripts, collector and raw logs: [matrix records](https://github.com/QIU023/torchtitan_attention_residual/blob/main/phase13_k3like_48b_posttrain/REPORT_ARCH_MATRIX_2026-08-04.md) (report architecture, primary) and [the unchanged-architecture run](https://github.com/QIU023/torchtitan_attention_residual/blob/main/phase13_k3like_48b_posttrain/TWIN_MATRIX_2026-08-04.md) (plus defect history), [scripts](https://github.com/QIU023/torchtitan_attention_residual/tree/main/phase13_k3like_48b_posttrain/matrix_scripts), [100-step raw, unchanged architecture](https://github.com/QIU023/torchtitan_attention_residual/blob/main/phase13_k3like_48b_posttrain/twin100_raw.txt).

- **The compiled gaps are one upstream operator limitation, not ours**: `torch._grouped_mm` rejects a zero contraction dimension -- the weight-gradient shape a rank sees when it ends up with zero routed tokens in total, which the ep2 x TP/PP/CP combinations produce (per-group empties alone do not: `ep8_fsdp8` passes compiled unshimmed). Five-line reproduction, no model/compile/distributed, being filed against pytorch/pytorch; with a local [shim](https://github.com/QIU023/torchtitan_attention_residual/blob/main/phase13_k3like_48b_posttrain/matrix_scripts/gmm_shim.py) that re-strides exactly as the proposed patch would, every affected cell passes -- **the shim is ours, so the unshimmed numbers stay the reported ones**.
- **PP depth beyond the matrix**: `PP8xVP4` (32 layers, one layer per virtual stage, Interleaved1F1B) runs clean on our own flavor at `seq_len 1024`; the 8192 configuration the pressure test was built for exceeds this box and is pending bigger hardware. [Details](https://github.com/QIU023/torchtitan_attention_residual/blob/main/phase13_k3like_48b_posttrain/TWIN_MATRIX_2026-08-04.md).
- **A shared-code gradient fix fell out of the matrix**: TP-without-EP legs under-reduced gradients below the routed experts (3.10x whole-model grad_norm gap, invisible in loss -- Adam is scale-invariant); root cause in the shared MoE sharding config, reproduces on unmodified deepseek_v3, filed as #4054.
- **The released 2.8T config was audited against report Table 1** on a meta device: 2.779T total vs 2.78T, 105.8B activated vs 104.2B, layer composition / latent / experts / vision tower matching field for field; the MTP layer is in the report but shipped disabled (`num_nextn_predict_layers: 0`), and enabling it costs ~30B that Table 1's total does not appear to include -- [scale audit](https://github.com/QIU023/torchtitan_attention_residual/blob/main/phase13_k3like_48b_posttrain/SCALE_AUDIT_2p8t_2026-08-04.md).

Caveats, briefly: the 100-step runs overfit a smoke dataset (stability evidence, not convergence -- real pretraining runs are queued); the primary matrix runs the eager reference's architecture deliberately (its final layer is KDA where the report and the released config end global -- raised on that PR as a config question; the report-architecture rows above cover the corrected layout); cross-stack numerical alignment is deferred until we rebase onto that PR -- these tables show eighteen configurations of one stack agreeing, not two stacks agreeing. Environment: torch `2.14.0.dev20260802+cu130`, fla-core `0.5.1`, 8x RTX 5060 Ti -- which cells can run is hardware-dependent (details in the matrix records), the losses are not. `PP8xVP4` at seq 8192 and real-data long runs are pending bigger hardware and will be posted then, not implied now.

### The interfaces the PP and EP slices touch, and who adds them: we do

Nothing to merge yet and nothing we are asking anyone to build. **PP (slot C)**: the eager decoder loop already threads `(h_BLD, block_residual_TND)` through every layer; the two missing seams -- an optional initial-stack argument and a layer-range slice, returning the pair -- land as our PP PR's first, separately reviewable commit. **EP (slot B)**: the per-expert <-> grouped-GEMM conversion (bidirectional key map with sliced-tensor indexing, `...experts.3.w1.weight <-> w1_EFD[3]`, plus the grouped experts module) already exists on the branch and ships with that PR, composing with the eager per-expert adapter rather than replacing it. TP and CP need no seam and rebase cleanly.
