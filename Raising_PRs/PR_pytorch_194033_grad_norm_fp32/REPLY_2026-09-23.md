Point 3: agreed, the test asserted CPU/CUDA rounding on every device. It now runs only on cpu and cuda (`@onlyOn(["cpu", "cuda"])`) and keeps the exact values 258 and 256, which are what both kernels give when they accumulate bfloat16 in float32. I did not take the two alternatives. `onlyNativeDeviceTypes` still admits `mps`, `xpu`, `mtia` and privateuse1 (`NATIVE_DEVICES` on current main), so the literals would still run on MPS and XPU. Docstring: it now states the constraint. `dtype` must be a floating point type the inputs promote to (`torch.promote_types(input.dtype, dtype) == dtype`), which is what `linalg.vector_norm` and the foreach CUDA kernel enforce for real inputs; anything else raises.
