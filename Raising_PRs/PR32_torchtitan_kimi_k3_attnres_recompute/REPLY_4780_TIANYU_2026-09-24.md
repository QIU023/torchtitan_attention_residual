What the PR fixes, in plain terms: a Kimi K3 layer does not add its input to its output. It takes a weighted average of the outputs of the earlier blocks plus the running sum, and the weights are a softmax over depth, one score per source, `score = query · RMSNorm(source)`. The query is the learned `*_res_proj.weight`. Two things were wrong with that on main. The query started from `trunc_normal(std=0.02)`, so the first step mixed the sources with arbitrary weights, where the report starts every query at zero, which makes the softmax uniform and the layer a plain average. And the aggregation kept two FP32 copies of the whole `[tokens, stack, hidden]` stack alive from forward to backward, the upcast values and the normalized keys, about 1 GiB per call at `dim` 7168 with a stack of 8 and 2048 tokens; with activation checkpointing they are built again in recompute, so they set that call's peak.

On the hand-written autograd Function: agreed, and it is gone. It ran op by op and the PR's own table showed the forward 3 to 21 percent slower. The branch now does what the review suggested. The aggregation is a `Configurable` (`AttentionResidual`, a parameter-free `Function`), one per residual site, so the override mechanism has a node to swap; its default is the eager FP32 form main has today, unchanged. `torchtitan/overrides/fused_attnres.py` replaces it with `fla.ops.attnres.fused_attnres`, the fused Triton op with an online softmax over the sources that saves only per-token statistics and rebuilds the upcasts in backward. `fla` stays optional: without it, or off CUDA, the override falls back to the eager form. The weights keep their names and their places on the block, so checkpoints, the state dict adapter and the sharding config are untouched. For SPMD type checking the fused op is registered with its eager decomposition, so the checker traces plain ops and never runs the kernel.

Checked that fla's op is Kimi's aggregation: RMSNorm weight folded into the query, softmax in FP32, the running sum as the last source, one rounding at the end. Against the eager form on random inputs the forward and all four gradients agree to 1e-5 relative in bfloat16 and 1e-7 in float32; at zero initialisation both return the mean of the sources and give the norm weight no gradient. The 4-GPU multimodal cell with strict type checking runs with the override on.
