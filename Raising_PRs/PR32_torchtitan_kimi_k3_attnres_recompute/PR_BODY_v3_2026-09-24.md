## Summary

Make Kimi K3's attention residual a configurable function and recompute it in backward with torch_remat, so a layer no longer keeps two FP32 copies of the block stack for backward.

- `torchtitan/models/kimi_k3/model.py`: `_apply_attention_residual` becomes `AttentionResidual`, a parameter-free `Function` whose default is the reference FP32 implementation. Each block holds one for its attention residual and one for its feed-forward residual, and the model one for the output residual, so the override mechanism has a node to swap.
- `torchtitan/models/kimi_k3/model.py`: each aggregation runs under `remat.checkpoint` when autograd records it and no activation checkpointing policy wraps its block. `KimiK3Model.parallelize` marks the blocks that selective, full and region AC wrap.
- CPU tests for the config nodes, the recompute (bitwise against the unwrapped call, the number of calls, no stack-shaped saved tensor), region AC and the marking in `parallelize`.

## Design

The reference form concatenates the block stack and the running sum, upcasts them to FP32, and keeps the upcast values and the normalized keys for backward: two FP32 copies of a `[tokens, blocks + 1, dim]` tensor per call. Section 5.2.2 of the Kimi K3 technical report wraps this computation in checkpointing, so that a layer saves what a standard residual saves. `remat.checkpoint` does that here, and backward reruns the aggregation from the stack and the running sum, which are kept anyway. The output aggregation sits outside every block and always takes its own checkpoint.

Selective, full and region AC already recompute each block, so there the aggregation runs as a plain call inside that checkpoint. Region AC's block checkpoint is a torch_remat one, which rejects a nested checkpoint; under the other two a second checkpoint would only run the aggregation again. The mark is set in `KimiK3Model.parallelize`, where the policy is built, and read at the call site, so the checkpoint wraps whichever implementation the config node builds.

The norm and projection weights keep their names and their places on the block, so checkpoints, the state dict adapter and the sharding config are untouched.

## Relation to #4656 and #INIT_PR

#4656 proposed the same checkpoint on the tree before #4810. Its change and its tests are carried here, on the configurable function, with the marking moved into `KimiK3Model.parallelize`. The zero initialisation of the residual projections, the other change in this PR's first version, is #INIT_PR.
