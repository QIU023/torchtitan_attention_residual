## Top-level reply

Thanks for the review. All 18 comments are addressed on the rebuilt stack, rebased onto current main (`da2f82670`) so CI can run:

- The vision tower is tensor-parallel now: it takes Kimi K2.5's MoonViT plan through the common helpers (`set_vision_transformer_block_sharding_config`, `vision_colwise_config`, `vision_scaled_bias_rowwise_config`, `invariant_norm_config`), and K3 customises only its projector (norm after the second linear). The invariant override, `_set_vision_encoder_tp_invariant_sharding`, is gone.
- The multimodal splice follows Kimi K2.5 / Qwen3.5: the token embedding stays replicated on TP when a tower is present, the scatter indexes the whole sequence on every rank, and layer 0's input boundary restores the decoder's layout (sequence shard under SP, invariant otherwise). No process-group attribute on the model, no DTensor branches in `_prepare_multimodal_embeds`, no re-shard in `forward`.
- The core changes are reverted: `common/attention.py` (the invariant-tower head split) and `common/linear.py` (RouterGateLinear on local shards) are back to main's; every tp cell runs without them on spmd_types.
- `set_tensor_parallel_sharding_config` is folded into `set_kimi_k3_sharding_config(enable_ep, enable_tp, enable_sp)`, called after `Decoder.Config.update_from_config`; CP is out of this stack; the KDA capability commit is dropped; MLA uses `local_head_split` and the two suggestions are applied; the SP splice unit test is deleted, the b200 cell `kimi_k3_mm_tp2` is the coverage.
- The one commit that stays at the bottom is the K2.5 tables retype, because K2.5 itself needs it: on `da2f82670` the K2.5 debug model at dp2 x tp2 with type checking fails at the shared position tables with `mutate_type: expected current type R on axis mesh_tp, got I`; with the commit it gets past them (and then hits K2.5's own `QK clip scales do not match the MLA weight shape` under TP, a separate problem). Happy to split it into its own PR if you prefer.

On our 8-GPU box (3 steps, seed 42, deterministic, spmd_types, 4096 tokens per step, loss at steps 1 / 3; the type-checked cells at the recipe's batch): tp=1 is bitwise with main (12.53584 / 6.63797 at this batch; 12.53909 / 11.37444 / 10.01040 at the recipe's, both with main's grad norms); tp=2 SP on 12.56396 / 6.53527, tp=2 SP off 12.55333 / 6.81346, dp2 x tp2 12.53445 / 7.02513, dp2 x ep2 x tp2 12.52623 / 7.00102; with `--debug.spmd-typechecking` the b200 cell (tp=2, SP on) reads 12.49262 / 11.38085 / 10.23243 (deterministic across two runs), tp=2 SP off 12.48463 / 11.41571 / 9.89427, dp2 x tp2 12.56306 / 11.38314 / 9.64091. With type checking at the same 4096-token batch and a seed-42 init per cell (no shared seed checkpoint): tp=1 12.51269 / 9.93869 / 7.14302, tp=2 SP on 12.45116 / 9.86473 / 7.14307, tp=2 SP off 12.44463 / 9.90965 / 7.12468. tp=4 with the multimodal debug model is now refused by the head-count check (the tower has 6 heads); the previous head's tp=4 rows ran with the tower replicated. The 100-step tables for the PR body will be re-measured on this stack.
