## Summary

Kimi K3's attention residual runs under a `torch_remat` checkpoint, so backward recomputes its FP32 intermediates instead of keeping them, as section 5.2.2 of the Kimi K3 technical report describes ("The AttnRes computation is entirely wrapped with checkpointing, so the activation saved for the backward pass at each layer is identical to that of the standard residual architecture").

- `kimi_k3/model.py`: each aggregation runs under `remat.checkpoint` whenever autograd records it and no activation-checkpointing policy already covers its block; the output aggregation always takes its own.
- `KimiK3Model.parallelize` marks the blocks that selective, full or region AC checkpoints, and their residuals run as plain calls inside that checkpoint.

## Design

The aggregation upcasts the blocks and the partial sum to FP32 and keeps (N + 1)-entry intermediates for backward, so each layer's saved activations grow with the number of blocks. Under a checkpoint, backward recomputes them from the blocks and the partial sum, which are kept anyway, so the per-layer saved set matches a standard residual block at the cost of running the aggregation again. Values are unchanged.

Selective and full AC already checkpoint the whole block, where a second checkpoint would only recompute the aggregation again, and RegionAC's block checkpoint is a `torch_remat` one, which rejects a nested checkpoint; so `KimiK3Model.parallelize` clears the flag for those three policies. The output aggregation on the head sits outside every block and always takes its own checkpoint.
