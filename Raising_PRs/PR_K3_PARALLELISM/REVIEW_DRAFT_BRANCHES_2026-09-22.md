## PP balance (`k3_pp_balance`, `080f44208`, 3 files, +427/-1)

Two correctness findings, the first not previously recorded anywhere.

- **Multiple source ranks overwrite each other's pool.** Every rank builds its own allocator at `pp_balance.py:181` while the pool base comes from the single destination entry at `:178-180`. The knob is a tuple and `install_pp_balance` supports several sources, so two sources both get offset zero, write the same destination memory, and fetch each other's bytes: silent wrong gradients. The 09-16 smoke ran one source, so the path never executed. Verified by reading; not reproduced on GPU.
- **The pool is freed inside unpack**, `pp_balance.py:247-263`, and the allocator has no double-free guard, so any schedule that consumes saved tensors twice (zero-bubble splits the backward, and the branch keeps `dw_builder`) corrupts the free list. Inferred from `saved_tensors_hooks` semantics, not reproduced.

Three abstraction violations the rules name explicitly: an instance monkeypatch of `stage.forward_one_chunk` at `pp_balance.py:325-329` when the branch's own `AttnResPipelineStage` already overrides that method; a side object attached to core's schedule at `parallelize.py:338-344` with a pyrefly suppression next to it; and an environment-variable switch at `pp_balance.py:153`. There is also an `atexit` print at `:190-194`. Reuse: `_stages_of` re-derives what `_swap_in_attn_res_stages` already computes and what the caller already holds, and returns an empty list when it cannot, after which the installer logs "parks of 0 stages" and does nothing; the 512-byte alignment at `:91` and `:102` is `torchtitan/tools/utils.py:23 round_up`. Comment plus docstring is 55 of 308 added non-blank production lines, 17.9 percent, including an 18-line module docstring carrying mechanism, a measured claim and packaging notes. Nothing constructs the knobs anywhere in the branch: 253 production lines whose only test covers the pool allocator. The body is in the right shape but its paste section discloses neither blocking issue, carries no numbers, and its planned table is three columns rather than the hundred-step form the rules require.

The integration tree already ports the same feature at `pipeline_parallel/__init__.py` (`vit_dep_split` plus the runtime install), so the rebase is a port from the tree rather than a merge.

The structural finding is that everything is installed by replacing methods on live objects: the tower stage's `forward_one_chunk`, then every stage's again in the runtime, then `backward_one_chunk`, and `pp_schedule.step` wrapped three times with the ordering held together by a comment. The branch's own `AttnResPipelineStage` already overrides both stage methods, which is the seam this should use. `dep_bubble_plan.py:211-236` rebuilds a torch schedule through `__new__` and eight private attributes to drive a fake stage, and those 61 lines exist only for tests.

Three docstrings contradict the code they sit on: the prefetch side stream is dead in training because `_vision_stream` returns None whenever grad is enabled, yet three docstrings describe the overlap as the point of the file. The planner silently drops every placement whose anchor is a backward while still counting them, so a schedule whose idle slots follow backwards warns every step and never fires. `_kimi_k3_vit_dep_split` duplicates `_kimi_k3_pipeline_split` in the same file and a third copy sits in the recipe, when core's `_get_pipeline_metadata` and `_generate_llm_fqn_per_model_part` do it. ## Dynamic CP (`k3_cp_mm`, `774e0b9b5` on 4639's `e06dcbee3`)

The first of its two commits does not apply to today's upstream main and does not need to: it adds `exclude_fqn_prefixes` to a `ContextParallelTransform` whose `inner_attention` is a per-type mapping, which is PR 4639's shape, while main's transform takes a single class; and main's `VisionAttention.Config` does not inherit `BaseAttention.Config`, so main's transform never reaches the tower and the exclusion has nothing to exclude. The model-side commit is portable: it only assumes `cp_enabled`, a CP mesh group and spmd types.

The abstraction finding is `setattr(model, "_cp_group_all", ...)` at parallelize time, read back with `getattr` in the model, when `spmd_mesh_group(MeshAxisName.CP)` is the seam the tree already uses; the failure mode is a silent fall back to the replicated tower when the attribute is missing. Subgroup construction is eager and quadratic in the divisors, 1920 communicators at cp 8 on a thousand ranks, where torch has `new_subgroups_by_enumeration`. The CP attention override drops the base class's remat regions, so the path that exists to save memory silently ignores the model's recompute policy, and it copies `_qkv` line for line. A module-level `spmd.register_local_autograd_function(dist_nn._AllGather)` changes process-wide typecheck behaviour on import and keys on a torch private class. Comment plus docstring is 274 of 706 added non-blank production lines, 38.8 percent. The body's three tables name no hardware at all (the earlier draft did), sit on trees that are not this branch, run three steps, have no noise-floor row, and one of them shows the partitioned tower further from the single-device reference than the replicated one without saying so; two changed files are missing from the list, including the core transform.

2. PP balance: fix the multi-source pool and the free-in-unpack before anything else, move the hooks into the stage subclass that already overrides them, and drop the env switch.
