## 3. `context_parallel.py:70` -- MLA Ulysses, "extra comms", value against all-gather, `fused_mla`

The boundary is clean and the kernel takes it as is: q, k, v after rope. What differs is what travels. MLA's k is `[k_nope | k_rope]` with the same rope vector on every head, so the generic all-to-all carries the rope slice once per head. This kernel sends `q | k_nope | v` in one all-to-all and the rope slice once, as a `[T/cp, R]` all-gather, and expands it on the local heads: one all-to-all plus a small all-gather instead of three all-to-alls, fewer bytes, not more.

Against all-gather KV: the all-to-all moves 1/cp of the packed tensor per rank, the all-gather moves the whole K/V to every rank. Equal at cp = 2; Ulysses wins as cp grows, and needs `n_heads % cp == 0`.

`fused_mla`: not tested. It attaches to the BSHD `FusedMLAAttention` with position ids; `KimiMLAAttention` is T-major, so the override does not attach to this model today. The kernel sees only the boundary's q/k/v, nothing in it depends on how k was assembled, so they should compose once it does; I will not claim it before running it.

Both MLA kernels are optional. The generic 4322 / 4450 kernels run this model unchanged and are bitwise with the packed ones at step 1 (the four cp2 rows of the table, 12.53972). If you prefer this PR minimal I will drop the two MLA kernels here and bring the packed variants as a follow-up; @fegin suggested keeping them for the bandwidth, either way works for me.
