> It seems `_get_pipeline_metadata` can handle the option of `if layers_per_stage is not None`.

Agreed; the next push removes that refusal. It is the assertion @tianyu-l asked for ([here](https://github.com/pytorch/torchtitan/pull/4312#discussion_r4056259393)), which replaced clearing `pipeline_parallel_layers_per_stage` on the copy passed to `pipeline_llm`. My reply there gave the wrong reason for it: the derived split was already sized by the knob through `_get_pipeline_metadata`. The clearing existed only because `dataclasses.replace` re-runs `ParallelismConfig.__post_init__`, which then rejected a split and the knob set together ([here](https://github.com/pytorch/torchtitan/pull/4312#discussion_r3984964516)). That check has since been removed.

The knob now sizes the derived split and stays on the copy, as on main. `qwen3_5`, `qwen3_6`, `qwen3_8`, `kimi_k2_7` and `muse_glimmer` accept it under PP again, and Kimi K3 accepts it too. On the current head they raise; CI never hit this because only llama3 recipes set the knob. The split check stays: `BaseModel.pipeline` sends a configured split straight to `pipeline_llm` ([here](https://github.com/pytorch/torchtitan/pull/4312#discussion_r4090997460)), so this function refuses one rather than replace it. `test_layers_per_stage_sizes_the_derived_split` covers a knob whose stage count differs from the default.

@tianyu-l, this removes the assertion you asked for. Nothing clears the knob anymore, so the user's value is kept. Happy to keep the assertion if you prefer the restriction.
