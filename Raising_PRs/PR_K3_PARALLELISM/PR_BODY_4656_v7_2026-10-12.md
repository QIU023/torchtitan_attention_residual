## Summary

Carry Kimi K3's attention-residual blocks inside the model as a list of [T, D] tensors instead of a [T, N, D] stack, so a block opening appends a reference instead of building a longer copy, and the activation checkpoints of later layers share the same blocks.

- `kimi_k3/model.py`: the blocks are a list, and `AttentionResidual` takes the list of sources it attends over and stacks it inside its compiled region. The model's forward still takes and returns the stack, so the pipeline stage is unchanged.
- `kimi_k3/sharding.py`: the layer 0 boundary of the multimodal decoder converts no stack, since the list starts empty.
- `torchtitan_recipes/overrides/kimi_attention_residual.py`: the Triton override takes the same list.

## Design

- List carrier:
  - Every block opening used to concatenate a longer stack, and each layer's checkpoint kept the stack it was called with.
  - Under full, selective or region activation checkpointing every shorter copy stayed alive until backward: 17 layers in blocks of 4 hold 10 extra [T, D] units.
  - A checkpoint keeps its inputs by reference, so with a list every checkpoint references the same blocks.
  - The block returns its output and the blocks as one flat tuple, since a function under `torch_remat` region checkpointing may return only one hop of tensors.
- Compiled aggregation (local compile from #5033 stays on):
  - The region takes one list, the blocks followed by the partial block, the way FLA's `fused_attnres` takes its residuals.
  - Dynamo specializes a list on its length, so the region compiles one graph per source count: 5 for `debugmodel`, 8 for `Kimi-K3`.
  - The region sets `recompile_limit=32`, since a fullgraph region fails at dynamo's default limit of 8 instead of falling back.
  - With a constant source count per graph the generated kernels differ from main's, so the numerics are not bitwise to main.
  - Results set that gap next to the one between main's compiled aggregation and its eager one.
- Triton override:
  - It stacks the list into the `[T, N, D]` bank its kernels read, and keeps the sources rather than the bank for backward.
  - The stack adds one copy of the sources per call in each direction.
  - A follow-up can read the sources by pointer, as FLA's operator does, and drop that copy.
