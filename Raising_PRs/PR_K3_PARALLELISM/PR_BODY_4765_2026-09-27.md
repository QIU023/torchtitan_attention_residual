## Summary

Every tensor a Kimi K3 pipeline stage's forward saves takes a `torch.utils.checkpoint.CheckpointPolicy`, and the ones marked `MUST_CPU_OFFLOAD` wait in pinned host memory until backward.

- `ActivationStorage` and `HostBackend` (`torchtitan/distributed/activation_storage.py`, new): apply a `CheckpointPolicy` to each tensor autograd saves inside a stage's forward, through `torch_remat.saved_tensors_hooks`. `{MUST,PREFER}_SAVE` leaves the tensor with autograd. `{MUST,PREFER}_CPU_OFFLOAD` copies it to pinned host memory on a side stream, within a host budget, and backward reads it back `prefetch_n_layers` layers ahead. A pinned storage stays on the device whatever the policy says.
- `KimiK3Model.Config.pp_memory.cpu_offload = "all"`: `MUST_CPU_OFFLOAD` for every save outside the model's last layer, with `cpu_offload_budget_gib` and `cpu_offload_prefetch_n_layers`. The rank store pins every block it holds, and the saves a stage's backward reads first come back when the rank's previous compute action begins. Off by default.

## Design

The storage executes core's `CheckpointPolicy` in eager training. graph_trainer marks a traced graph with the same values: `tag_all_offloadable_activations` sets `MUST_CPU_OFFLOAD` and `apply_cpu_offload_pass` inserts the copies. Core's eager selective checkpointing treats the CPU offload values as recompute, so an eager run has had no executor for them. titan's activation checkpointing runs on torch_remat, whose `saved_tensors_hooks` receives every saved tensor with the context it was produced in; the storage is that hook. `cpu_offload = "all"` follows the graph pass's defaults: every save outside the last layer, a host budget, one layer of read ahead.

The storage lives in `torchtitan/distributed` because nothing in it is specific to Kimi K3. The rank store pins through the storage's API, so the storage never needs to know what an AttnRes block is.
