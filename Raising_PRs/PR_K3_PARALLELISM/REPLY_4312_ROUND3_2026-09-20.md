## Thread 6, `torchtitan/models/kimi_k3/model.py:242` (discussion_r4056308907)

--- PASTE BEGIN ---

A block's column enters the stack at the block's first layer, by a `torch.cat` on the stack that layer received: with 8 layers in blocks of 4, block 0's column at layer 0 and block 1's at layer 4. Every later layer reads the whole stack, so a column is live from its own layer to the head's aggregation in the forward, and in the backward until the earliest layer holding it has run. At the end of the forward the two stack tensors hold three columns between them, [T, 1, D] and [T, 2, D].

A partial sum lives one layer. The layer adds its attention output to the sum it received and hands it on, the next layer's residual read consumes it, and it is released after that layer's backward, the same life cycle a plain residual's hidden state has. It never crosses a block boundary: the block's first layer puts it into the stack instead and starts a new one.

What a layer keeps beyond that is the residual read's own fp32 intermediates, which is where the saved set stops looking like a plain residual block. #4656 puts that computation under a checkpoint so the backward recomputes it; under selective or full AC the block's own checkpoint already does, which is why that PR marks the block rather than nesting a second one.

Its follow-up, #4780, rewrites the body so the call saves per-token statistics instead of those intermediates. The two compose, and both are filed against main, since the same function is the head's aggregation.
