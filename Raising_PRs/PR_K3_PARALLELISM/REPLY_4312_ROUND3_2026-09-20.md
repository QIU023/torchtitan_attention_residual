## Thread 6, `torchtitan/models/kimi_k3/model.py:242` (discussion_r4056308907)

From the code, checked with a `saved_tensors_hooks` probe on the new 8 layer debug model (`logs_pp_round3_2026-09-20/saved_probe.py`, one GPU, no PP, T = 256). The measured totals are memory bookkeeping (shapes and dtypes), not numerics.

--- PASTE BEGIN ---

Without PP, 2 blocks x 4 layers (the debug model now has exactly this shape), T tokens, D the model width. Three things are alive at the end of the forward, each with its own release point.

1. The stack. `torch.cat` at a block's first layer makes a new tensor: layer 0 turns the empty stack into [T, 1, D] (the embedding output e), layer 4 turns that into [T, 2, D] (e, x4). Layers 1 to 4 receive the same [T, 1, D] object, layers 5 to 7 and the output aggregation the same [T, 2, D]. No op saves the bf16 stack itself (cat's backward is a split, the fp32 upcast's backward needs no input), so without AC the [T, 1, D] object is gone as soon as layer 4's cat has read it. With AC (the flavor's default `SelectiveAC`, or full AC) every layer is one checkpoint region whose inputs are saved, and the inputs are h [T, D] and the stack, so the [T, 1, D] column is held by the regions of layers 1 to 4 and the [T, 2, D] column by those of layers 5 to 7: three columns of [T, D] in total, N(N + 1) / 2 for N blocks, one storage each (the probe sees layers 2, 3 and 4 reference layer 1's storage and 6, 7 reference layer 5's). Released in the backward when the last region holding it has run: [T, 2, D] after layer 5's backward, [T, 1, D] after layer 1's.

2. The partial sum of the open block, one [T, D] per layer, the residual stream between the block's first layer and the current one. A plain residual net keeps exactly this; it lives until that layer's backward. Under AC it is recomputed, not kept.

3. The residual read itself, `_apply_attention_residual`, twice per layer (before the attention, before the FFN) and once at the head. Each call upcasts the stack plus the partial sum to fp32 and keeps, until that layer's backward, `values` and `keys` in fp32 of shape [T, N + 1, D] (N + 1 = 2 in block 1, 3 in block 2) plus a [T, N + 1, 1] and a [T, N + 1] vector. Without AC this is what makes the saved set unlike a standard residual block: 16 bytes x T x (N + 1) x D per call, 8 MiB per layer in block 1 and 12 MiB in block 2 at T = 256, D = 1024. `SelectiveAC` saves linear, mm and attention outputs only and recomputes everything else, so these upcasts are recomputed in the backward and nothing of the residual read survives the forward except the stack columns of point 1. That is what the report's "entirely wrapped with checkpointing" comes to: per layer the saved set is h and the stack, the standard residual's h plus N(N + 1) / 2 columns for the whole model.

Measured on the debug model at its round 3 depth (2 blocks x 4 layers), T = 256, dim 1024, one GPU, memory left allocated after the forward above the parameters: no AC 383 MiB (94 to 113 MiB per layer, of which the residual read's fp32 tensors are 8 to 12), `SelectiveAC` 63 MiB, full AC 15.5 MiB; the three stack columns are 1.5 MiB in both AC modes.

On the bot's summary: the three column count and the fp32 upcasts being the dominant term both hold, with one correction. Without AC the bf16 columns are not retained by the graph, no op saves them; what is retained is their fp32 upcast inside each residual read. The three columns are the AC picture, which is the flavor's default.

#4780, filed against main because the same function is the head's aggregation, replaces the body of `_apply_attention_residual` with an `autograd.Function` whose forward saves the bf16 stack and partial sum (references, no copies) plus three fp32 vectors of shape [N + 1, T] per call (the softmax probabilities, the scores and the inverse rms) and whose backward recomputes the fp32 upcasts one column at a time. Without AC the saved set per call goes from two fp32 [T, N + 1, D] tensors to those vectors, and the stack columns then live as long as the count above says, N(N + 1) / 2 of them in bf16, under AC or not.
