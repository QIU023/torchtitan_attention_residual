# dynamic CP 和 main 的 #5266（视觉塔 CP-invariant）冲突（2026-10-15，CPU 会话）

用户："拉取 检查栈分支和视频pr分支"。检查栈分支时发现：栈上的 dynamic CP（#4380 的 squash，代码和 PR head `097068e0f` 逐字相同）建在 `b663c1673` 上，而这个 base 已经包含 main 的 #5266。#4380 自己的 base `01b1b69e3` 不包含 #5266。

## #5266 改了什么（Jessica，10-11 合入，`3210be829`）

- 标题："Make the vision encoder CP-invariant, only dp_shard"。
- 视觉塔的参数和激活在 CP 上都声明为 invariant（`_vision_state_placement(..., cp=spmd.I)`、`_vision_activation_placement(cp=spmd.I)`）。`multimodal_input_sharding` 的 docstring 写："Each CP rank processes the full vision input"。
- 视觉塔的 FSDP 只在 dp_shard 上切（`resolve_fsdp_mesh(parallelism_context, shard_on_cp_axis=False)`），参数梯度不再沿 CP 归约。
- 改由输出边界对输出梯度在 CP 上做 all-reduce（PR 正文："Declarative output boundaries sum CP gradients"；表里的 "CP output-gradient all-reduce"）。
- 前提是每个 CP rank 算的是同一份 tower，梯度天然相同。

## 和 dynamic CP 的冲突（按代码推断，待 GPU 探针确认）

dynamic CP 让每个 CP rank 只编码自己那一段（band），正好打破这个前提：

1. **大图特征的梯度被放大 C 倍。** 输出边界做完 all-reduce 后，每个 rank 拿到的是整份 bank 的完整梯度 G。`_assemble_bank` 里的 `all_gather_parts` 用 `dist_nn.all_gather`，它的反向是 reduce-scatter 求和。于是 band 的属主 rank 拿到 Σ_r G_band = C·G_band（C 是 CP 大小）。
2. **各 CP rank 上的 tower 副本会慢慢分叉。** rank r 的参数梯度是 g_whole + C·g_split(r 自己的 band)，各 rank 不同；而 #5266 之后没有任何东西沿 CP 把 tower 的参数梯度归约。各 rank 用不同的梯度更新各自的副本，副本从第 1 步起就不再一致。
   - 各 rank 梯度的平均值恰好是正确的总梯度，但没有人去求这个平均。
3. **类型检查发现不了：** `all_gather_parts` 把每一份按输入的类型重新标成 `I@CP`，`VisionCPLayout` 的 gather 也在类型检查之外，所以 band 不一致这件事不会被 spmd 报出来。

**K/V gather 不受影响：** 子组内的 K/V gather 反向求和是对的。每个 rank 的 query 对 K/V 贡献的是各自不同的部分梯度，求和就是总梯度。

**影响范围：**
- 栈上所有开 dynamic CP 的格子（h100 的两个 CP 格子、DEP + dynamic CP 那组、3584 大图和视频那组）：rc 0、loss 看起来正常，但正确性没有被证实。
- #4380 rebase 到 main 之后同样会这样：
  - 现在和 main 有文本冲突（flavors.py、model.py、vision_encoder.py、h100.py，来自 #5280 等）；
  - 但真正的问题是这个语义冲突，单纯 rebase 解决不了。
- AdamW 会把梯度的整体缩放归一化掉，所以只看 loss 很难看出问题；副本分叉才是硬伤。

## GPU 探针（确认用）

- 树：栈 `c7ca6fb1a`，或者 #4380 rebase 到 main 后的临时树。
- 配置：CP 2、dp 1，dynamic CP 阈值 128（每张图都切），AdamW，seed 固定，跑 1 到 2 步。
- 看两样：
  1. 第 1 步之后，两个 CP rank 上视觉塔参数的最大差：开 dynamic CP 时预期不为 0（分叉），关时预期逐位相同；
  2. 第 1 步视觉塔的梯度，开和关对比：大图那部分的贡献预期是 2 倍。

## 修法方向（要用户定，大概率要和 Jessica 商量）

1. **开 dynamic CP 时，视觉塔回到 #5266 之前的机制：** FSDP 在 dp_shard × cp 上切（`shard_on_cp_axis=True`），输出边界不做 all-reduce，按部分梯度传。#4380 当初就是在这个机制下设计和验证的（`948d65c86`，GPU 测试和 bank 替换都成立）。代价是要动 #5266 的声明式类型：dynamic CP 开的时候，tower 不能再标 `I@CP`。
2. **保留 #5266 的机制，在 dynamic CP 内部补偿：** bank gather 的反向只取自己那份、不求和；整图的梯度在每个 rank 上乘 1/C；再对 tower 参数梯度沿 CP 做一次显式 all-reduce。要加一个梯度 hook，比方案 1 更绕，也和 titan 的接缝规则不合。

我的倾向是方案 1：dynamic CP 本来就要 tower 在 CP 上分工，tower 就不是 CP-invariant 的，类型应该如实反映这一点。但这是对 #5266 设计的例外，需要先和 Jessica 对齐。
