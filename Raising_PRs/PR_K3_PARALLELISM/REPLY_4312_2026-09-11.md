### #1 (3984841792) — debug model size

Parameter counts of the debug model (meta build, width and vocab as in `_debugmodel`): 33 layers = 1.40 B parameters, of which the embedding and the head are 335.5 M (the vocabulary is the real one) and each layer 32.2 M; 17 layers (19 units, which pp 2/4/8 do not divide either) = 0.89 B; 13 layers (15 units) = 0.77 B. 33 was chosen so the unit count reproduces the 93-layer model's uneven split (two full blocks of 12 plus a partial block of 9) and no pipeline shape divides it; 17 keeps the "no shape divides" property but has a single partial block. If 1.4 B is too large for CI, 17 layers is the smallest shape that still exercises an uneven split with a partial block; say the word and I move every number in the PR to it.

### #2 (3984853855) — `first_layer_in_block`

Done: computed once in `__init__` (`b5bb7b315`).

### #3 (3984964516) — `pipeline_parallel_layers_per_stage=None`

Done both ways: `ParallelismConfig.__post_init__` raises when `module_fqns_per_model_part` and `pipeline_parallel_layers_per_stage` are both given (`b9e7cf8e7`, with a config test), and the pipelining entry no longer rewrites the config at all — the split is core's now (#4), so there is nothing to set to None.

### #4 (3984970518) — extend core's generator

Done: `_generate_llm_fqn_per_model_part` and `pipeline_llm` take `first_stage_modules` / `last_stage_modules`, module names pinned next to `tok_embeddings` / after `norm, lm_head`, counted as no layer. With the defaults every existing split is byte-identical (checked on 441 combinations of stages, layers and the two weights against the previous function, and the new `test_pipeline_llm_split.py` pins three shapes). ### #7 (3985185896) — the eager init, and @sanketpurandare's question

That code is off this PR (the transport commit now lives on `k3_pp_transport`). To the question: `init_process_group(device_id=...)` makes NCCL create the default communicator at init instead of at the first collective; main's `torchtitan/distributed/utils.py` does not pass `device_id` today, so the default communicator is created lazily at the first collective and the sub-group communicators at mesh build (`ncclCommSplit`), which is what the INIT log of a pp8 run on this branch shows — and nothing lazy during the schedule. The port passed `device_id` only under its opt-in flag; on one node it changes nothing observable.
