## 4. PR A

### 4.0 新 torch 上 PR A 原样跑不了（09-29 07:21 发现）

- **现象：** 源码编的 09-28 torch 上，PR A `85eefa54b` 的 PP 单测 2 个失败（`test_forward_only_eval_between_steps`、`test_rank_cache_matches_whole_stack_and_single_device`），报 `PipeliningMetadataError: Receive buffer for 'recv_for_4_from_3' is still owned by an incomplete pipeline step`。带 PR A 提交的 dev 分支也一样：dev 3 个、#4765 4 个、#4764 7 个失败。main `5dc97a3e7` 67 个全过。日志在 `results/cpu_tests/`。
- **原因：** torch 在 09-22 合入了 pytorch#196463（"[pipelining] Allocate receive buffers just in time"，提交 `6f8b7008e7`）。接收缓冲现在由 torch 自己在 recv 之前分配（`_RecvInfo.allocate_buffer`），计算接手时交出（`take_buffer`），同一个缓冲被设两次就报这个错。PR A 的 `get_fwd_recv_ops` / `get_bwd_recv_ops` 先自己设 `info.buffer` 再调 super，正好撞上这个检查。09-23 以后的 nightly 都有这个改动。
- **发送那一半 torch 没改：** `_PipelineScheduleRuntime` 仍然把所有 send 放进 `send_ops`，整步结束才等（这个 build 的 `schedules.py` 第 3163 行）。
- **影响：**
  - main 从 09-26 起本来就要 09-26 以后的 torch（#4540、#4592），所以在任何能跑 main 的 torch 上，PR A 的接收那一半都是多余的，而且会报错。
  - PR A body 里"torch 每个 micro-batch 给每个输入和输入梯度各留一个接收缓冲、整步不放"这句，对现在的 torch 已经不成立。torch issue 草稿（`TORCH_ISSUE_PP_BUFFERS_2026-09-27.md`）的接收部分已经由 torch 自己做完，只剩发送部分。
  - 5060 上 PR A 的数字（09-06 的 torch）里，有一部分是 torch 现在自己已经省掉的。
- **这次怎么量（分支没动）：**
  - 新 torch：main 对 PR A 的"只保留发送"探针（`pra/pra_send_only_probe.patch`：去掉四个接收覆盖和两处缩缓冲的循环，发送等待保留；新 torch 上 67 个 PP 单测全过），量 PR A 在现在的 torch 上还剩多少。另跑 2 步 PR A 原样，记下训练时怎么失败。
  - 旧 torch（cu126 09-06，接收缓冲按 micro-batch 预分配，打兼容补丁）：main 对 PR A 原样，即 PR A 当初针对的情况；dev 对它的父提交；#4765、#4764 冒烟。
- **PR A 接下来怎么改由你定。** 我的建议：PR A 只留发送那一半（去掉接收覆盖，body 的 Summary 和 Design 改成只讲发送），torch issue 只提发送。

### 4.1 用户 09-29："PR A后续的实验结果是重复4312的矩阵结果吗？"

- 原计划不是：只排了 dim 6144 放宽模型 pp4 × vp2 的显存和计时。现在把 4312 的 H100 矩阵加在 PR A 那部分最前面（`pp4312/`）：照 4312 的协议（c4 文本行、每种 batch 一个 seed checkpoint、fp32 grad norm、100 步、参考先冷编译一次再在拷贝上跑、所有格子拷参考的缓存），格子照 4312 的表 A 和表 C。每一格 main 和 PR A 各跑一遍，新 torch，PR A 用只保留发送那一半的探针版本。
- 4312 的探针补丁移植到了 `5dc97a3e7`（`pp4312/probe_apply_5dc9.py`，`parallel_dims` 改名 `parallelism_context`）；c4 flavor 放在本地模块 `pp4312/pp4312_local.py`，不再往 `config_registry.py` 里追加；16 个 stage 的切分照 4312 当时 `ce67cece4` 的 `kimi_k3_debugmodel_pp4_vp4`。4312 的表 B（fp32）不跑。
- `5dc97a3e7` 上 `default_adamw` 已经删了，4312 矩阵的 recipe 和 PR A 的放宽探针都改成 `OptimizersContainer.Config(optimizers=[AdamW.Config(pattern=r".*", lr=8e-4)])`，机器上逐个建过。
