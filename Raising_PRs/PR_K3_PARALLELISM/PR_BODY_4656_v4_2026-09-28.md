## Summary

Wrap Kimi K3's attention-residual computation in checkpointing, so backward recomputes it, as described in section 5.2.2 of the Kimi K3 technical report ("The AttnRes computation is entirely wrapped with checkpointing, so the activation saved for the backward pass at each layer is identical to that of the standard residual architecture").

- Run `_apply_attention_residual` under a `torch_remat` checkpoint in `kimi_k3/model.py` whenever autograd records it and no activation-checkpointing policy already covers the block, for the two residuals of every block, and always for the output aggregation.
- Mark the blocks in `KimiK3Model.parallelize` when selective, full or region AC checkpoints them, so their residuals run as plain calls inside that checkpoint.
- Carry the blocks as a list of [T, D] tensors that every layer shares instead of a [T, N, D] stack that each block opening copies, so every checkpoint references the same blocks (`kimi_k3/model.py`, `kimi_k3/sharding.py`, and the call into the model in `kimi_k3/pipeline_parallel/stage.py`).
- Add CPU tests: gradients bitwise against the unwrapped residual, the residual math run once more in backward, no stack-shaped saved tensor, and a block opening that appends the blocks it was given.

## Design

The residual stacks the blocks and the partial sum, upcasts them to fp32 and keeps the (N+1)-entry intermediates for backward, so each layer's saved activations grow with the number of blocks. Under a checkpoint, backward recomputes them from the blocks and the partial sum, which are kept anyway, so the per-layer saved set matches a standard residual block at the cost of re-running the residual math. Values are unchanged.

The saved set matches a standard residual block in every mode. With activation checkpointing off, the model guarantees it: each residual is a `torch_remat` checkpoint. Selective and full AC wrap the whole block in a torch checkpoint, which already keeps these intermediates out of the saved set, so `KimiK3Model.parallelize` marks the block (`checkpoint_residual = False`) and its residuals run as plain calls; a second checkpoint inside would only recompute them again. Under RegionAC the block is a `torch_remat` checkpoint too, so the same flag applies. The output aggregation on the head stage sits outside every block checkpoint and always takes its own.

A checkpoint keeps its inputs by reference. With a stack, each block opening concatenates a longer copy, and every earlier layer's checkpoint keeps the stack it was called with, so all the copies live until backward: a CPU count with 24 layers in blocks of 4 finds 21 [T, D] units alive where the blocks are 6, the same under full, selective and region AC. The blocks therefore travel as a list. A block opening appends to it, `_apply_attention_residual` stacks the list inside the call, and every checkpoint references the same blocks. The pipeline stage passes its assembled stack in as views and reads the returned list, so the transport is unchanged.

## Results

One H100 (80 GB), cells run one at a time, this PR `f14d681f4` against its base, main `f35966713`. The model is the debug model as it is on main, `kimi_k3_debugmodel` (dim 256, 17 layers in attention residual blocks of 4, 25.8 M parameters); the previous revision's tables used the larger debug model of `a3a819c67`. dp1, bf16, `seed=42`, deterministic, 2048 tokens per step in 512-token micro-batches, 10 steps, one inductor cache shared by every cell and warmed by a 1-step run of each; the fresh-cache row is main with activation checkpointing off, warmed and measured again on a cache of its own. Loss and grad norm are compared at all ten steps; peak memory is the max reserved figure the trainer logs; tps is the mean over steps 6 to 10.

```bash
torchrun --nproc_per_node=1 -m torchtitan.train \
  --module kimi_k3 --config kimi_k3_debugmodel --debug.seed 42 --debug.deterministic \
  --training.steps 10 --training.num-tokens-per-train-step 2048 \
  --training.num-tokens-per-microbatch-per-dp-rank 512 activation-checkpoint:none
```
