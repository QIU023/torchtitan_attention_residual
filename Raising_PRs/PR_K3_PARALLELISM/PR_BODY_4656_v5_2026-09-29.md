## Summary

Wrap Kimi K3's attention-residual computation in checkpointing, so backward recomputes it and each layer saves the same activations as a standard residual block, as described in section 5.2.2 of the Kimi K3 technical report.

- Run `_apply_attention_residual` under a `torch_remat` checkpoint in `kimi_k3/model.py`, for both residuals of every block that no activation-checkpointing policy covers and always for the output aggregation.
- Mark the blocks in `KimiK3Model.parallelize` when selective, full or region AC checkpoints them, so their residuals run as plain calls inside that checkpoint.
- Carry the blocks inside the model as a list of [T, D] tensors instead of a [T, N, D] stack (`kimi_k3/model.py`, `kimi_k3/sharding.py`). The model's forward still takes and returns the stack, so the pipeline stage is unchanged.
- Add a CPU test of the recompute: gradients bitwise against the unwrapped residual, the residual math run once more in backward, no stack-shaped saved tensor.

## Design

The residual upcasts the blocks and the partial sum to fp32 and keeps the (N+1)-entry intermediates for backward, so each layer's saved activations grow with the number of blocks. Under the checkpoint, backward recomputes them from the blocks and the partial sum, which are kept anyway.

Selective, full and region AC already checkpoint the whole block, so there the residuals run as plain calls instead of a nested checkpoint. The output aggregation sits outside every block and always takes its own.

A checkpoint keeps its inputs by reference. With a stack, each block opening makes a longer copy that stays alive in the checkpoints reading it until backward; with a list, every checkpoint references the same blocks.
