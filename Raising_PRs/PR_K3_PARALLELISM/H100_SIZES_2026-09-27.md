## 3. PP：main、#4656、#4780、PR A、全叠

- **结构（记录：5060 上 PR A、#4765、#4764 的全部 PP 实验，`kit_pp_lowerbound_2026-09-26/results/INDEX.md` 的 s4、s5、s6）：** 93 层、block 12、每 stage 3 层（32 个 stage）、seq 2048、16 个 micro-batch、FullAC、seed 42、Interleaved1F1B。8 卡是 pp8 × vp4，4 卡是 pp4 × vp8；切分由 `_generate_llm_fqn_per_model_part(32, 93, 1, 1)` 给出，两种卡数完全一样。
- **宽度：** **dim 7168**，就是发布模型的 hidden size，其余照 5060 的探针（16 头，dense hidden 2 × dim，小 MoE，vocab 2048；`kit_pp_lowerbound_2026-09-26/probe_lb.py`）。这样层数、block 和 hidden size 都是发布模型的，只有 seq 和 MoE 是探针的。
  - 怎么定的（推算，`kit_h100_sizing_2026-09-27/`）：5060 上用同样的 pp4 × vp8 实测 main（这张表里最重的树）在 dim 1024 和 1536 两格，第 3 步每个 rank 的峰值 7.95 / 8.69 / 8.68 / 8.48 和 11.64 / 12.58 / 12.57 / 12.30 GiB；每个 rank 的静态部分按 meta 上数的参数算（16 B/参数），其余按宽度线性外推。
  - 预计 main 每个 rank：dim 4096 最大 32.1 GiB，**dim 7168 最大 55.5 GiB**（55.3 / 55.5 / 55.4 / 54.3），dim 8704 最大 68.1 GiB。要把 main 推到 70 GiB 左右就得比发布模型还宽，所以取 7168。
  - 这是从 1536 外推到 7168，上机第一步用 main 跑 2 步核对。
- **每格：** 一份预热 cache（每格各跑一步预热，再各拷一份），10 步看每个 rank 的峰值和逐位一致性，第 8 步 trace 计时（`campaign2.sh` 的协议）。FullAC 下 #4780 只在 output aggregation 上多一个 checkpoint（block 里的两个 residual 在整个 block 的 checkpoint 里照常调用），所以 #4780 列除最后一个 stage 外应当和 #4656 相同，全叠同理对 PR A；这两列用来证明这一点。

## 5. DEP 放大版：没有记录可沿用，要你定模型

- **已有（实测，09-27 H100）：** 已提交的格子（现在的 debug model，pp4 × vp2，M8）是 launch bound 的：1.24 s 的调度跨度里 GPU 只算了 53 到 63 ms。数值、放置计数、百步、混合数据都已经做完；只有"气泡省了多少时间"没法在它上面量。
- **决定气泡价值的是视觉塔一次编码和文本 stage 一次前向的计算量比 c。** 只算矩阵乘，c = 视觉塔参数 ÷（每 stage 层数 × 每层激活参数）× 4f，f 是图像 token 在序列里的占比（spatial merge 2 × 2，一个图像 token 对应 4 个 patch）。参数在 meta 上数（推算，`kit_h100_sizing_2026-09-27/dep_ratio.py`，输出 `dep_ratio.out.txt`），每 stage 按 3 层：

| 模型 | 视觉塔 | 每层激活参数 | 视觉塔 ÷ 3 层 | c |
|---|---:|---:|---:|---:|
| 发布的 Kimi-K3 | 447.4 M | 1107.7 M | 0.13 | 0.54 f |
| 现在的 debug model（已提交的格子） | 3.3 M | 0.98 M | 1.12 | 4.5 f |
| 09-17 的 debug model（第 2 节） | 36.5 M | 15.3 M | 0.79 | 3.2 f |
| 第 3 节的 PP 文本（dim 4096）加发布的 MoonViT | 434.8 M | 42.2 M | 3.44 | 13.8 f |

- 有出处的几个组合，c 都是发布模型的 6 到 26 倍：视觉塔相对文本太重，放大后测出来的是一个视觉塔主导的流水线，不代表发布模型。要保持发布模型的比例，文本每层的激活参数要约为整个视觉塔的 2.5 倍（1107.7 ÷ 447.4），这需要一个新设计的模型（比如发布模型按同一比例缩窄文本和视觉塔）。这一步要你定；在你定之前，DEP 在 H100 上只用 09-27 已有的结果。
