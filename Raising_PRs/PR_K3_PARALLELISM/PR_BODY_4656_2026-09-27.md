## Summary

Kimi K3's attention residual keeps each block once, as one list every layer shares, and recomputes its aggregation in backward instead of keeping the FP32 intermediates, as section 5.2.2 of the Kimi K3 technical report describes ("The AttnRes computation is entirely wrapped with checkpointing, so the activation saved for the backward pass at each layer is identical to that of the standard residual architecture").

- The block residual (`kimi_k3/model.py`): a list of [T, D] blocks instead of a [T, N, D] stack. A block opening appends to the list; it used to concatenate a longer stack, and every earlier layer's checkpoint kept the shorter stack it had been called with. The aggregation stacks the list inside the call, so its arithmetic is unchanged.
- The recompute (`kimi_k3/model.py`): each aggregation runs under a `torch_remat` checkpoint whenever autograd records it and no activation-checkpointing policy already covers its block; the output aggregation always takes its own. `KimiK3Model.parallelize` marks the blocks that selective, full or region AC checkpoints, and their residuals run as plain calls inside that checkpoint.
- The pipeline stage (`kimi_k3/pipeline_parallel/stage.py`) hands the model its assembled stack as views and takes its commits and payload from the returned list; core still reads the input gradients off the stack leaf. The multimodal decoder boundary (`kimi_k3/sharding.py`) converts no stack any more, since the list starts empty and its first block is layer 0's converted input.

## Design

With the stack, each block opening makes a longer copy, and every earlier layer's checkpoint keeps the stack it was called with, so all the copies live until backward. A 24 layer model in blocks of 4 keeps 21 [T, D] units alive where the blocks are 6, and full, selective and region AC keep the same 21, since each block checkpoint takes the stack as an input too. With the list every checkpoint references the same six blocks.

The aggregation upcasts the blocks and the partial sum to FP32 and keeps (N + 1)-entry intermediates for backward, so each layer's saved activations grow with the number of blocks. Under a checkpoint, backward recomputes them from the blocks and the partial sum, which are kept anyway, so the per-layer saved set matches a standard residual block at the cost of running the aggregation again. Selective and full AC already checkpoint the whole block, where a second checkpoint would only recompute the aggregation again, and RegionAC's block checkpoint is a `torch_remat` one, which rejects a nested checkpoint; so `KimiK3Model.parallelize` clears the flag for those three policies. The output aggregation on the head sits outside every block and always takes its own checkpoint.

## Results

8 x RTX 5060 Ti, one card per cell, this PR against its base, main `f35966713`: the debug model, bf16, `seed=42`, deterministic, 2048 tokens per step in 512-token micro-batches, 10 steps, one inductor cache shared by every cell and warmed by a 1-step run of each; the fresh-cache row is main with activation checkpointing off on a cache of its own. Peak memory is the max reserved figure the trainer logs; tps is the mean over steps 6 to 10.

```bash
PYTHONPATH=<attention-gym main>:. torchrun --nproc_per_node=1 -m torchtitan.train \
  --module kimi_k3 --config kimi_k3_debugmodel --debug.seed 42 --debug.deterministic \
  --training.steps 10 --training.num-tokens-per-train-step 2048 \
  --training.num-tokens-per-microbatch-per-dp-rank 512 activation-checkpoint:none
```
