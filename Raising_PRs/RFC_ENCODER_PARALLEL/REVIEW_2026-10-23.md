## 必须改（事实或规则）

1. **Megatron-Core 那条不成立：**
   - References 里的文档链接 404（curl 和 WebFetch 都是）；
   - 现在的 Megatron-Core `ModelParallelConfig`（0.15 到 0.18.1 的 API 页）没有任何 encoder 专用的并行大小字段；
   - 建议删掉 TP 行的 "a smaller TP degree for the encoder (Megatron-Core)" 和 References 那一条。
2. **GLM-5V-Turbo 的出处是 RL 一节：**
   - §2.4 的标题是 "Multimodal RL at Scale"。数据加载侧的 CP / TP 切分、异步 all-to-all、联合 bin-packing、ViT 的 recompute 加 offload 都在这一节；
   - RFC 的表格和 "Approaches" 都没说是 RL 训练，应注明 "(RL training, sec 2.4)"。
   - Summary 说 "The DeepSeek, GLM and Qwen frontier models describe the same decoupling of the encoder from the language model's parallel layout"：
     - DeepSeek-V4.1-Flash（encoder 复制在 LLM 参数树外，三段式）和 Qwen3.5（"decouples parallelism strategies across vision and language components"）是解耦；
     - GLM-5V-Turbo 做的是把视觉输入的 CP / TP 切分挪到数据加载，不是同一种解耦。这句话应该只举 DeepSeek 和 Qwen。
3. **#4381 表少了条件：**
   - 线上 body 原文是 "full activation checkpointing; the Kimi K3 debug model widened to dim 6144 with its 2-layer debug ViT, at most one image per sample"，另有 "of which 13 carry an image"；
   - RFC 只写了 "widened to dim 6144"。不写 2 层 debug ViT，读者会以为是 27 层的 MoonViT。
4. **#4381 表测在哪棵树上，要写清楚：**
   - 这张表是 10-04 在当时的 PR head `8518f473f`、旧 main 上测的；PR 现在是 rebase 后的 `7529daeea`；
   - 10-19 在新 head 上的 H100 重测只有 48% 到 52%：被 trace 的一步多了 30 多秒空闲，profiler 下有 5160 次 C++ 异常，原因没定位（`../PR_K3_PARALLELISM/H100_RERUN_4380_4381_2026-10-19.md`）；
   - 规划器从 `8518f473f` 起没变。RFC 的 "both PRs will be re-measured" 是如实的，但维护者现在复测会拿到 50% 左右；
   - 建议说明里写上测量日期和当时的 head。未定位的 48% 到 52% 按数值规则不进 RFC。

## 设计层面（维护者大概率会问）

5. **没提 #5266：**
   - 开 dynamic CP 时 encoder 不再是 CP-invariant：tower 在 CP 上标 R，梯度在各 rank 是部分和，FSDP 改在 dp_shard x cp 上切，靠 #4380 在 common 加的 `MultimodalModel._encoder_is_cp_invariant`；
   - 这是 Jessica 的 #5266 的例外，`../PR_K3_PARALLELISM/NOTE_JESSICA_DYNCP_5266_2026-10-16.md` 一直没发；
   - 通用化以后，每个打开 dynamic CP 的模型都走这条路。RFC 的 dynamic CP 一条应该加一个子 bullet。
6. **运行时换 `__class__`：**
   - 粘贴区写的是 dynamic CP "swaps the encoder's class for a CP subclass the way `fully_shard` does"，DEP "swaps their class for a DEP subclass"；
   - titan core 没有这种先例：main 上 `__class__ =` 只出现在 experiments（`graph_trainer/simple_fsdp.py`、`transformers_modeling_backend`）；
   - 两个 PR 现在也不是这么做的：
     - #4380 是 `KimiK3VisionEncoder(MoonViTCPEncoder)`，加上 flavor 里的 `VisionCPAttention.Config`；
     - #4381 是建 stage 时组合 `_VisionDepAttnResStage(VisionDepPipelineStage, AttnResPipelineStage)`，schedule 外面包一层 `VisionDepSchedule`；
   - 按 seam 优先的规则，可以改成由 config 选：encoder 的 `Config` 加一个 dynamic CP 字段，`build()` 组合出 CP 子类，FQN 一样不变；DEP 由 `pipeline()` 选 stage 类；
   - 也可以保留换类的写法，但要准备好维护者的反对。这一条由用户定。
7. **DEP 的梯度怎么回到唯一一份 encoder，没写：**
   - #4381：每个 PP rank 一份副本，前向不存激活，反向重算；
   - 副本梯度先在 PP 上 reduce 到 stage 0，再在 DP 上 all-reduce，写进 FSDP 管的 stage 0 encoder 的 `.grad`，所以优化器和 checkpoint 只看到一份 encoder；
   - #5250 之后副本要用 reduce dtype 累加（`caa8726fa`，只在 `dep_review1`）；
   - 建议给 DEP 加一个子 bullet。
8. **没写挪到哪：**
   - "Two opt-in wrappers in common" 和 "move out of the Kimi K3 folder unchanged" 都没给目标位置；
   - #4577 的写法是每个组件写明放在哪。

## 措辞和格式

9. "every encoder in the tree already has this signature" 改成 "every vision encoder"：
   - Muse Spark 的 audio encoder 也在 `multimodal_encoder_fqns` 里，签名是 `(waveforms_SC, *, waveform_padded_lengths_N)`；
   - NaViT 的参数名是 `pixel_values_NP`。
10. DP / FSDP 和 TP 两行的 "Covered, not implemented" 读起来自相矛盾（covered 一般理解为已处理），建议 "Not proposed here"。

12. 嵌套 bullet 规则：Evaluation 和 DeepSeek-V4.1-Flash 两条，每条都有两句能独立的话，要拆成子 bullet。
13. Summary 第一句讲问题，第二句才讲提案。按 PR 文本规则，第一句应该直接说这个 RFC 提议什么。
14. "able to follow as soon as it lands" 和 Users 里 "Qwen3.5 还要写 band 位置和 merge" 对不上，建议 "can follow by implementing the contract"。
15. （可选）Muse Spark 的第一 stage 上还有 `audio_encoder` 和 `perception_emb_norm`。DEP 只复制视觉的三个模块的话，audio encoder 仍留在 stage 0。
