## Done this session

**Fixed and verified**

* CP multimodal deadlock -- a zero-sentinel CP shard dropped the vision tower
  out of the loss graph, so that rank skipped an FSDP reduce-scatter its peers
  issued. Found by diffing per-rank collective traces.
* PP tuple -- non-last stages return `(hidden, block_residuals)`; both
  tower-alive call sites assumed a tensor.
* PP gradient density -- `pp8` on 13 layers failed torch's P2P density check;
  the last stage's aggregation makes the partial-block gradient a strided slice.
  Fixed with a dense-grad barrier on PP **inputs** (two earlier attempts targeted
  outputs and the adapter, neither of which is in the path).
* PP checkpoint namespace -- only the `embed_tokens` stage is re-wrapped as the
  multimodal model, so other stages named parameters without the
  `language_model.` prefix. **Multimodal + PP could not load any checkpoint**,
  resume included. Cold-start matrices could not see it.
* Twin flavor fidelity -- `training.dtype` was float32 where the eager PR sets
  bfloat16, which put KDA on fp32 operands and blew this GPU's shared-memory
  limit on three cells.
* KDA `A_log`/`dt_bias` stored at the default dtype rather than hardcoded fp32
  (FSDP2 rejects non-uniform dtype). Bit-identical under the fp32 default.
* MTP layer implemented, default off. **Training loss is NOT wired** for
  multi-token targets; that needs the trainer's loss interface to carry more
  than one head. Architecture only.
* 2.8T multimodal flavor (`kimi_k3_2p8t_vl`); scale audit against report Table 1
  passes field-for-field (2.779T / 105.8B against 2.78T / 104.2B).
* veRL flavor discovery -- `_discovered_flavor_names()` filtered on a
  `kimi_linear_` prefix, so the rename made all 37 new flavors invisible to
  veRL. Its own docstring describes this exact failure class.

## LoRA TP: what is established and what was my error

**Established.**

* `q_a_proj.lora_b`'s gradient is identical across ranks on layer 0 and differs
  on layers 1, 2, 3. Direct per-parameter comparison.
* With LoRA off the same architecture is clean: 40 replicated gradients checked,
  all agree.
* The gradient chain through `q_a_layernorm` reduces correctly: Partial
  output-grad differs per rank (0.000193 / 0.000178), Replicate input-grad is
  identical (0.000596 both).
* Baseline on this tree: 26 replicated gradients checked, 11 disagree -- three
  `q_a_proj.lora_b` (layers 1-3) plus eight AttnRes projections, which are
  downstream and clean without LoRA.

**My errors, both the same error.**

I twice reported a defect by comparing values that are *supposed* to differ
across ranks: `Shard(2)`-placed locals, and plain per-rank tensors such as
`o_proj`'s input (the local attention-head shard). That produced a false
"forward diverges" conclusion, which is impossible anyway because `lora_b` is
zero-initialised and contributes nothing to the forward at step 0.

**The next measurement, written so it cannot repeat that.** Compare only
gradients whose placement is Replicate on the TP axis. Walk layer 1's backward,
find the first Replicate-labelled gradient whose values differ, confirm the same
point is clean on layer 0. Never compare plain per-rank or Shard-placed locals.

Two earlier fix attempts both edited `LoRALinear.forward`; neither could work if
the defect is in what reaches the module.

## Things that will bite the next session

* **Never edit a source file while a matrix is running.** Two matrices were
  discarded for this.
* **Wipe the per-leg dump folder** or the trainer resumes instead of
  restarting, and the collector reads short output as failure. Cost three
  matrices.
* **`EADDRINUSE`** is the one transient failure actually observed. Retry on a
  fresh port and only for that.
* **Disk.** Per-leg checkpoints plus inductor cache filled 380G once, to the
  point where the harness could not write its own output. Set
  `--checkpoint.interval` high.
* **`PYTHONPATH` must be absolute.** The shell cwd does not persist between
  tool calls, so `$PWD` silently points at the wrong repo.
* **No issue or PR numbers in commit messages.** Roughly 14 cross-reference
  events were already pushed onto someone else's PR timeline before this rule
  existed; they cannot be removed.
* **The scripts are in `phase13_k3like_48b_posttrain/matrix_scripts/`** now, not
  `/tmp`. Its README carries the environment and the hardware-specific findings.
